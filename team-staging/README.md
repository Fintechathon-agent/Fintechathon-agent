# 临时共创区 · 可以修改和联调

这里供全体成员放入正在开发的代码、待测试的模块和接口样例，方便大家一起修改、排查问题和联调。

**当前状态：共创目录已建立，尚未汇总全员代码。这里的内容默认是待验证版本，不能直接当作正式交付。**

## 怎么放东西

当前可联调模块：[长文本生活资金与风险](risk/long-text/README.md)（本地网页、解析/纠错 API、周期收支与风险测算；已测试待联合确认）。

1. 在本目录下新建自己的模块目录。建议使用 `core-agent/`、`ui/`、`risk/`、`data-memory/` 等清楚的名称；同一模块需要独立试验时，再增加实验子目录。
2. 从原有目录复制需要共同调试的内容，保留原件，不整仓覆盖。不上传依赖缓存、`.env`、令牌或真实账户资料。
3. 把[交付说明模板](DELIVERY-TEMPLATE.md)复制为该模块的 `DELIVERY.md`，说明来源、怎么启动、测试情况、已知问题和待对齐事项。
4. 修改共同模块前先看已有说明，避免覆盖队友的工作。涉及其他模块或已锁定公共接口的变更，由对应负责人确认。
5. 验证通过后，按仓库审核要求把确认好的内容复制到[正式交付区](../team-release/README.md)，并补充版本记录。

## 正式与临时的区别

| 临时共创区 | 正式交付区 |
| --- | --- |
| 可以放未完成内容，但必须标明问题 | 只放已测试、已确认的交付内容 |
| 用于共同修改、实验和联调 | 用于共同使用、演示和交付 |
| 不保证所有模块能一起运行 | 只按已有验证证据声明可用范围 |

“临时”表示开发阶段，不表示会自动清空。旧版本通过 Git 提交保留；没有确认时不要删除队友的文件。

## 使用边界

- 不上传群聊记录、成员昵称对照、内部身份分析或未经授权的真实用户资料。
- 演示数据必须标明，真实服务调用失败时保留失败状态，不能改成演示成功。
- Core Agent 不重新计算 Quant、不修改 Memory 规则；资金动作继续经过 Risk 和必要审批。
- 本目录不会自动同步到正式区，也不会自动部署；已有定时日报不等于全员代码自动交付。
- GitHub 编辑权限仍由仓库控制，文件夹名称本身不提供独立权限隔离。
