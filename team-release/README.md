# 正式交付区 · 团队共同使用

这里放全体成员已经测试、确认可以一起使用的代码、接口说明和交付文档，作为团队共同演示与交付的版本。

**当前状态：共享目录已建立，尚未汇总全员代码，也没有统一启动入口。此目录暂不代表完整产品已集成或上线。**

| 目录 | 放什么 | 怎么改 |
| --- | --- | --- |
| **team-release（本目录）** | 测试通过、相关负责人确认的共同交付成果 | 先在临时区验证，再按仓库审核要求更新到这里 |
| [team-staging（临时共创区）](../team-staging/README.md) | 开发中、待测试、需要大家共同修改的内容 | 可以修改和联调；修改其他人的模块前先与负责人对齐 |

## 放入正式区前

1. 在临时共创区完成修改和测试，并填写[交付说明](../team-staging/DELIVERY-TEMPLATE.md)。
2. 涉及接口、风控状态、审批或错误码的变更，先在团队协作记录中说明，由相关负责人确认；不要自行改变已锁定的约定。
3. 按仓库审核要求提交变更，只把已确认的代码和必要资料复制到正式区的对应模块目录。保留原始来源和历史版本，不直接搬走或覆盖个人目录。
4. 在[版本记录](CHANGELOG.md)中写清来源提交、测试结果、确认状态和回退依据。

建议按模块存放，例如 `core-agent/`、`ui/`、`risk/`、`data-memory/`；这些只是目录建议，目前未创建，也不代表已有对应运行服务。多个模块共同使用的接口和启动方式，应在首次完成集成后补充到本说明中。

## 共同规则

- 正式区用于稳定交付；开发和实验先放临时区。名称不会自动限制 GitHub 编辑权限，审核与合并仍按仓库权限和协作约定执行。
- 标清成果属于“演示覆盖”“接通真实系统”还是“通过联合验收”，不要混写。
- 不上传密钥、真实账户资料、群聊记录、成员昵称对照或内部身份分析；配置说明只使用占位符。
- Core Agent 不重新计算 Quant、不修改 Memory 规则；模型建议必须经过 Risk 和必要审批，未接执行网关时保留阻断。
- 目录本身不提供自动同步、自动部署或成员权限隔离。现有个人目录和已部署服务继续保留。
