## 一、选题逻辑：为什么是「六场景全覆盖 + 理财深度路径」

赛题要求「至少覆盖 3 个核心场景（鼓励全覆盖）」，评分=任务完成率 40% + 安全性 30% + 创新性 30%。
我们的策略是**广度与深度各取所长，但安全承诺一寸不让**：

1. **六场景全覆盖**（转账 / 账单 / 理财 / 卡片 / 订阅代扣 / 跨场景联动）——任务完成率口径上
   不丢任何场景分，且每个场景都能现场演示、全程可审计；
2. **理财操作保持深度路径**——理财是六场景中唯一"资产动账 + 红色强验证"的场景，
   安全要求的天花板落在安全工程积累（30% 评分权重）上；完整可信闭环
   （意图 → 诊断 → 建议 → 闸门 → 推演 → 强验证 → 纸交易 → 审计 → 记忆）原样保留；
3. **广度不以牺牲安全为代价**——新场景不是"浅覆盖"，每个场景都有确定性域闸门：
   转账有收款人/余额/限额/防重复闸门，卡片有存在性/状态机/额度边界闸门，
   订阅有存在性/重复取消闸门；全部走绿黄红三级权限与统一审计、统一熔断。

**一句话定位（PPT 第一页可用）**：
> 《金融 AI 安全任务台》——银行 AI 智能体，六个场景全覆盖，理财路径做深成可信闭环。
> 每个场景都过同一道闸：意图路由 → 确定性闸门 → 绿黄红分级 → 审计留痕。
> 广度是覆盖，深度是信任，安全是底线。

## 三、核心差异化叙事（创新点怎么讲）

1. **记忆投毒防御（主打，原样保留）**：写入侧信任分级 + USER/MENTAL_MODEL 层禁止直写 + 读取侧 spotlighting。
   背书：MITRE ATLAS `AML.T0080 AI Agent Context Poisoning`；OWASP LLM01 缓解第 6 条。
2. **确定性风控闸门（fail-closed）扩展到全场景**："LLM proposes, Python disposes"——
   理财 7 项交易闸门 + 转账/卡片/订阅各自域闸门，任何检查抛异常一律保守拦截。
3. **五层演化记忆的工程洞察**：跨天证据才涨置信度、去重增强只升不降、reflect 按证据天数提炼规则。
4. **六场景统一安全框架**：一条防线（注入检测）→ 一个路由（闭集）→ 一套权限（绿黄红）→
   一份审计 → 一个熔断器——场景越多，安全代码复用越多，而不是安全承诺变薄。
   （这是与 Revolut AIR 类产品最本质的差异：AIR 重交互广度，我们重"每个动作都可证明其安全"。）

## 六、评委预期追问与回答口径（Q&A 预演）

- **Q1：「六场景是浅覆盖吗？」** → 不是。每个场景都有确定性域闸门与权限分级，转账/卡片/订阅
  的拦截规则当场可演示（未知收款人、余额不足、重复挂失、重复取消全部被闸门拦下）。
  广度是场景数，深度是安全保证——两者不互斥。
- **Q2：「自然语言入口在哪？」** → 顶部六场景统一入口（一句话路由）+ 右侧组合体检输入框。
  演示「平安银行卖出 30%」可见意图、槽位与执行 DAG；说「你定吧」会拒绝替用户做资金决定。
- **Q3：「和 OpenClaw / Revolut AIR 比，你的创新在哪？」** → 差异化在安全纵深：
  确定性闸门 + 记忆投毒防御 + 五层记忆，对标"银行内控要求"而非"更流畅的聊天"。
  六场景统一框架让安全代码随场景复用，而不是随场景摊薄。
- **Q4：「记忆到底改变了什么决策？」** → 现状：recall 进入决策上下文 + reflect 生成心智模型提示；
  跨场景联动演示了记忆参与编排（生日 → User 相关事实 → 计划任务）。
  机制化联动（心智模型 → 审批阈值）在路线图。诚实回答比过度包装安全。
- **Q5：「异常熔断和沙箱呢？」** → 熔断已落地：六场景强验证失败与闸门拦截统一计数，
  连续 3 次锁定资金执行、查询保留、人工恢复；沙箱口径：不生成执行代码 + 结构化数据约束 +
  演示模拟执行隔离。
- **Q6：「安全怎么测的？」** → 86 个自动回归测试；54 条自然语言入口攻击全部拦截，
  20 条正常金融表达零误伤。数字只代表当前本地测试集，不夸大为未知攻击泛化能力。
- **Q7：「账单/订阅数据是真的吗？」** → 演示 fixture（source=demo），界面与报告均标注；
  订阅识别规则（同商户同金额跨 3 个月）与异常规则（大额/境外/深夜/重复/新商户）是确定性规则，
  接真实数据源时规则与口径不变。诚实标注是合规底线。
