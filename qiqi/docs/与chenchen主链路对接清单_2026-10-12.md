## 二、已对齐的共识

1. 公共接口锁定：契约只加可选字段，不改 `investment-agent.v1` 既有字段（双方各自 commit 里都有此口径）。
2. 金额/余额/权限结论由确定性规则产生，LLM 只解释结构化结果。
3. 真实资金动作不承诺；演示数据必须带 source/data_tag 标注。
4. 风险交接语义：他侧 `HANDOFF_REQUIRED` ≡ 我侧「黄/红待确认」，双方都不在交接点自动放行。

## 三、具体接入点（按优先级）

### P0 · 契约互通验证（半天）
- 用同一份样本（持仓 5 只 + risk_profile）同时跑他的 `runHealthCheckContract` 和我方 `/api/review`，比对：建议动作、gate 检查项、handoff 状态。
- 产出：一张字段映射表（他 `task_state.stage/checkpoint/artifacts` ↔ 我 `recommendation/gate/whatif/approval_id`），落成双方共同文档。
- 阻塞项：他方需给出可本地运行的 Core Agent 服务（4175）或 Cloudflare 端点白名单；我方需要他 sample portfolio 的 fixtures 文件。

### P1 · 理财审批握手（1 天）
- 方案 A（推荐）：我方 `/api/review` 产生的 `queued` 审批 → 序列化为他契约的 `PENDING_REVIEW` 交接包 → 他侧只读展示；他的"人工对照"结论回写我方 `/api/decide`。
- 方案 B：他 Core Agent 作为我方理财体检的另一个引擎（delegated 时二选一/对照跑），结果并排展示在「结果」页的"对照区"。
- 阻塞项：他 Risk Owner 回写接口（save/approve）的版本化契约；确定 HTTP 端点与鉴权（内网 172.27.253.10 还是 Cloudflare）。

### P2 · 店主场景真后端（1 天）
- 我方 merchant.html 的浏览器 harness 换成他 `merchant/ledger` 真服务：serve.py 加白名单代理（本地 4175 或他公网端点），账单/现金日历/试算全部走他接口。
- 阻塞项：他 merchant 路由的稳定接口清单（ledger/bills/cash/scenario/export）与金额单位口径（他分/我方元）。

### P3 · 审计与记忆合并（可选，2 天）
- 统一审计事件 schema（他 trace/audit events ↔ 我 JSONL 字段：ts、action、user、policy、input_hash、result、approval_id）。
- 记忆互通仅限 session-only 读取，不共享长期记忆写入门卫之外的数据。
