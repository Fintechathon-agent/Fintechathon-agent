## 三、给主链路的接入提案（供你决策，不先斩后奏）

新场景的请求/结果目前走 `/api/scenarios/run`（qiqi 自有 HTTP 面）。如果要把
六场景并入 investment-agent.v1 主链路，我建议的信封扩展是**可选字段**（不破坏既有调用方）：

```json
{
  "contract_version": "investment-agent.v1",
  "request_id": "...",
  "operation": "banking.scenario",
  "context": { "scenario": "transfer | bill | card | subscription | cross_scene", "text": "..." }
}
```

响应侧在既有 `task_state/artifacts` 之外加 `scenario_result`（tier/status/data），
旧调用方读不到该字段即视为无影响。**这只是提案**：是否采纳、字段怎么定，
由你按主链路 DRI 口径拍板；在你确认前我不会改 `/api/scenarios/*` 的输出形状。
