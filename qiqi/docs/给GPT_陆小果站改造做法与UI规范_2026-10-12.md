## 二、我是怎么做的（四步）

1. **读原站、列资产清单。** 把原站的设计价值逐项列出来：色板、玻璃拟态、侧栏工作台、journey-strip 流程条、eyebrow/terminal-label 标签体系、balance-card/环形图、product-stamp"虚构演示"印章、动效令牌（320ms / cubic-bezier(.22,1,.36,1)）、诚实标注等。这张清单是我后面"只删叙事、不删设计"的依据。
2. **把问题分成三层，只动后两层。** 视觉设计层：原样保留。业务场景层：原站是"个人投资顾问 + 店主财务助手"双场景，赛题是「AI 代人操作银行（安全+体验）」，团队已锁定产品为**安全银行任务执行台**，所以双场景叙事要全部重写成单一产品，店主场景（巷口咖啡应收应付）是赛道错位，要剔除。数据层：原站 versions/api.js 是浏览器内 mock harness，要换成团队真后端。
3. **用原站的设计 token 重建页面，而不是改原站页面。** 我选择了"新写一个单页工作台"的路线：`web/static/compare/`（index.html + compare.css + compare.js，共 687 行），直接复用原站的深色画布、橙金品牌色、玻璃卡片、侧栏、流程条、印章等设计语言，全部交互通过 `api("/api/...")` 走团队后端（web/app.py）。
4. **每个资金动作旁强制诚实标注。** `source: demo_fixture · as_of: 2026-10-11`、`FIXTURE / NO REAL MONEY` 印章、"金额由 Python 闸门决定，模型只解释"。

## 三、UI 设计规范（你的版本必须长这样）

### 1. 色彩（tokens）

- 画布：`#0b0a09`，次级 `#11100e`；页面背景叠一层右上角橙光径向渐变 `rgba(237,118,39,.16)`
- 品牌橙金三件套：`--orange #ed7627` / `--orange-soft #ffb36a` / `--orange-pale #ffe2ac`，阴影色 `#71300e`
- 文字：主 `#f8f3eb`，次 `#cfc4b5`，弱 `#8d8174`，最弱 `#655b52`
- 状态三色（权限分级专用）：绿 `#72c4a2`、黄 `#e4ae5c`、红 `#ed7c70`；聚焦环 `#ffd38e`
- 面板：半透明深棕 `rgba(27,24,20,.78)` + `backdrop-filter: blur(18px)`；描边 `rgba(255,237,210,.12)`

### 2. 字体

- 标题用衬线：`Georgia, "Noto Serif SC", serif`（hero 字号 clamp(31px, 4.5vw, 58px)，字距 -.035em）
- 正文用无衬线：`"PingFang SC", "HarmonyOS Sans SC", "MiSans", "Noto Sans SC", "Microsoft YaHei", system-ui`
- 标签/元信息用等宽：`ui-monospace, monospace`，9px、大写、字距 .1–.18em（eyebrow、terminal-label、panel-index、来源标注）

### 3. 布局骨架（自上而下）

1. **左侧 rail 侧栏**（220px，sticky，右侧 1px 描边，玻璃背景）：品牌位（K 币渐变徽标 35px 圆角 11px + "FINANCE LAB / SAFE TASK CONSOLE" 两行）、WORKSPACE 区（01 任务台 / 02 安全边界 / 03 审计回放 / 04 证据看板，等宽序号前缀，hover/active 橙色描边+微橙底）、底部 BASELINE 区（回主工作台链接 + 免责小字）
2. **topbar**：左侧 eyebrow 小标签 `FINANCE LAB / BANKING AGENT`，右侧圆角胶囊 chips（规则引擎·绿点、`演示固定数据` 橙色警示、人工恢复、回到主工作台 ↗）
3. **hero**：左侧 terminal-label + 衬线大标题（一行斜体橙色强调）+ 13px 说明；右侧右上角偏移的圆形橙色光环装饰；右上角 `FIXTURE / NO REAL MONEY` 印章（等宽 9px、细描边、rotate(2deg)）
4. **journey-strip**：三格流程条（01 说清楚 / 02 过闸门 / 03 人确认），格间橙色渐变细线；激活格橙色、完成格绿色、危险格红色
5. **data-strip**：状态数据条（演示环境·绿点 / N 条待确认 / 可用余额 / 执行链路正常 / `source · as_of` 等宽来源标注右对齐）
6. **work-grid 双列**：左"任务入口"面板（快捷任务胶囊 + 大 textarea 表单 + 橙色主按钮"生成安全计划 ↗" + 结果卡），右"任务轨道"面板（可回放执行计划节点列表：圆点状态 done/waiting/blocked + 绿黄红权限表 + 理财深度路径 callout）
7. **lower-grid**：事实卡（来源/截至/金额决定/真实动作 四格）+ 待确认队列（确认/拒绝/强验证输入/勾选）+ 审计回放面板

### 4. 组件语言

- 面板：圆角 16px、1px 弱描边、玻璃底、panel-kicker（橙色等宽小标 + 右侧 panel-index 弱色）
- 按钮：主按钮橙色实底圆角 7px 深色字；次按钮透明底描边；触控目标 ≥ 44px（快捷胶囊）/ 36px（小按钮）；全部有 hover 提亮、active 下沉 1px、focus-visible 2px 橙色环
- 徽章：权限分级永远用 绿/黄/红 三个 tier 圆角小方块，语义固定——绿=查询直返、黄=资金动作需确认、红=挂失/大额强验证
- 印章与诚实标注：任何涉及资金的区域必须出现"演示模拟 · 未发生真实资金转移"、`source` 和 `as_of`
- 状态卡：拦截/熔断用红描边红底（`rgba(115,33,31,.16)`），越界用黄描边，普通结果橙描边
- toast：右下角固定、橙描边、`translateY(12px)→0` 淡入

### 5. 动效与响应式

- 过渡 140–220ms，缓动 `cubic-bezier(.4,0,.2,1)`（出场可用 `.16,1,.3,1`）；交互反馈以颜色/描边变化为主，不做花哨动画
- 断点 930px：侧栏转顶部横条；断点 680px：topbar/hero 转单列、grid 全部单列、按钮全宽
- 必须支持 `prefers-reduced-motion`
- 桌面 1440 与移动 390 均不得横向溢出

## 四、你按你的方法做——两版要不一样

设计规范只约束"长得像"，不约束实现。以下维度你可以（也应该）走自己的路，这样两个版本并立时看得出是两个独立实现：

- **页面结构**：我走的是单页工作台；你可以做多页分栏、顶部 tab、或"主控台 + 详情抽屉"
- **组件实现**：我自己手写 CSS；你可以用你顺手的组件方案，只要视觉结果落在上面规范内
- **交互流程**：任务提交、确认队列、强验证的交互顺序和反馈方式可以自己设计（例如我可以是卡片式结果，你可以是时间线式）
- **文案口吻**：术语一致（安全任务执行台、绿黄红、闸门、审计回放），但句子你自己写
- **API 组织**：前后端接口契约不变（见下），前端状态管理、渲染方式随你

## 五、红线（两个版本都必须遵守）

1. 单一产品叙事：只讲「银行 AI 智能体 · 安全任务执行台」，不得出现"双场景""个人投资顾问 + 店主财务助手"并列叙事、巷口咖啡等旧业务文案
2. 绿黄红权限分级必须可见、可演示（黄=需确认、红=强验证、连续失败熔断+人工恢复、注入拦截不进入执行队列）
3. 所有资金动作旁有"演示模拟 / source / as_of"诚实标注，绝不假装真实银行或真实转账
4. 契约不动：只调用团队现有后端接口——`/api/scenarios/run|confirm|pending`、`/api/breaker/reset`、`/api/audit`、`/api/review`、`/api/decide`（见 `D:\黑客松大赛冲刺版\web\app.py` 与 `contracts/`），不新增接口、不修改后端
5. 不做会覆盖现有文件的破坏性改动；新增文件先放独立目录，每一步可回滚
