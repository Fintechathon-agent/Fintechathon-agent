# 随手记：生活与投资的统一入口

日期：2026-10-17。交付范围：本地可操作试用版 + 后续核心 Agent 接入规格。

## 1. 这次补充的产品定义

用户可以自然地讲一大段话，收入、投资、会员、吃饭、优惠需求和情绪混在一起。系统先区分事实、计划、请求和情绪，整理成各板块能使用的记录，再给一条简短、温和、可展开的回复。用户无需先选 Agent 或先填账本。

本次新增入口：`http://127.0.0.1:8765/team/journal.html`。现有工作台侧栏也可点击“随手记”。

| 输入片段 | 去向 | 状态与计算原则 |
| --- | --- | --- |
| 今天工资到账 12000 元 | 收入账本 | 自述收入，未与银行对账 |
| 打算拿工资的 30% 投纳斯达克 | 投资计划、记忆 | 同段且同月有唯一已到账工资时算出 3600 元；不记成交，不新增真实持仓 |
| 订阅 GPT Pro 花了 200 美元 | 订阅支出 | 200 USD 单列；本例金额来自用户输入，不是平台当前售价说明 |
| 中午猪脚饭实付 18 元 | 生活支出 / 餐饮 | 实付额入账，优惠券面额不再重复扣除 |
| 帮我找美团猪脚饭优惠券 | 优惠需求 | 提取餐饮与平台；尚未实际搜索、领取或购买 |
| 今天很烦，天气也不好 | 本轮回复语气 | 给予简短回应，不形成长期心理或关系画像 |

一句合适的回复：

> 今天听起来挺累的。我记下了工资、会员和午饭；纳斯达克的 3600 元放在投资计划里。美元扣款单列，你补一下生活预留后，我们再看本月空间。

这是产品口吻示例；当前页面根据实际记录数量与状态生成简短回复。

### 保存范围

- 原话发送到同源 Python 服务做规则解析，不发送任何模型供应商；服务不持久化原话。
- 结构化结果与预留存在此浏览器的 `finance-lab.journal.v1`；不同浏览器、设备不互通，清除站点数据会丢失。
- 原话仅在当前页面内存显示，刷新不保留。默认摘要去掉关系人姓名、天气与情绪，保留必要财务分类、金额和日期。
- 隐藏生活金额是显示控制，不是权限隔离或加密。共享电脑应使用独立浏览器个人资料。
- 删除记录会移除该条派生记忆，已导出的 CSV 属于独立文件。未建立不可变更审计账本。

## 3. 设计需求单

**界面类型**：现有 Finance Lab 工作台的独立补充页。

**视觉方向**：对话优先、渐进披露、克制的信息层级。沿用当前深棕底、橙色、字体与圆角；不增加新的装饰语言。

**模块清单**：

- 对话区：一列消息，长段输入 100–320px 高；每屏一个主要提交按钮。
- 归档结果：先 1–3 句短答，明细放可展开区域；每条保留类别、日期、状态及修改入口。
- 时间账本：按日期降序，月份与类别筛选；移动端堆叠列表，避免宽表格挤出屏幕。
- 记忆：事件摘要与关注权重分开呈现，区分最近记录和历史依据。
- 侧栏概览：桌面 280–300px，手机移至下方；收支与计划分行。
- 隐私显示：生活金额遮罩，导出时隐藏开关开启则排除生活与订阅明细。

**交互与动效**：点击反馈 ≤100ms；过渡 180ms；控件触控范围 ≥44px；键盘标签页、编辑弹层 Esc、中文输入法组合输入保护。

**内容与信息层级**：短回复 → 状态 → 金额 → 可展开依据；以实际记录状态决定反馈，不预先显示“投资已更新”。

**边界**：已有投资工作台、审批流程、共享接口契约保持原语义；本次独立扩展 `journal.v1`，需要团队联调时再做正式契约评审。

## 5. 核心 Agent 应怎样接入

长期结构是“一个入口协调者 + 明确的工具职责”，不需要让用户面对多个聊天窗口。下列为接入规格，不能宣传为已运行的多 Agent 系统。

```text
自然语言输入
  → 多意图提取（事实 / 计划 / 请求 / 情绪）
  → 数字、币种、时间、主体、否定、重复检查
  → 收支工具 / 投资工具 / 订阅工具 / 优惠查询工具
  → 跨场景现金流检查
  → 事实存储 + 可撤回的记忆更新
  → 一次简洁回复 + 展开明细

任何资金动作 → 原有权限、风控、人工确认、执行回执、审计
```

| 职责 | 只需要的上下文 | 输出 |
| --- | --- | --- |
| 入口协调者 | 当前文本、最小化相关摘要 | 多个事项、证据片段、歧义问题、工具调用计划 |
| 收支工具 | 事件日期、商户、币种、实付金额、账户来源 | 幂等收支记录与分类 |
| 投资工具 | 标的、方向、数量、价格、账户、已成交证据 | 待核验投资流水；对账后才形成持仓快照 |
| 订阅工具 | 商户、周期、币种、下次账期 | 订阅负担、续费提醒；取消仍需确认 |
| 优惠工具 | 商品类别、平台、城市、预算、资格 | 带来源、查询时间、有效期与到手价构成的优惠结果 |
| 跨场景风险工具 | 现金快照、待支付义务、投资计划、预留 | 缺口与可选调整建议 |
| 记忆管理 | 用户允许持久化的事实与来源 | 新增、更正、替代、过期、删除，不改写原始账务事实 |

金融工具通常不需要知道约会对象、私密对话或情绪原句。收支事实与投资分析可按用户授权共享，私人生活详情应独立控制访问。

### 接口落点

本地新增 `POST /api/journal/parse`：输入 `{ "text": "..." }`，输出 `version / engine / as_of / records / unclassified / empathetic`。空值、非字符串、超过 6000 字返回 400。

记录包含 `id / kind / category / title / amount_cents / currency / status / occurred_on / recorded_at / source / confidence / ratio / direction / notes / attention`。金钱用整数分，发生时间与记录时间分离。这个独立契约不替代已有 `contracts/`、MCP 或投资健康检查契约。

模型接入时保留确定性校验层。模型负责提取候选与提出必要问题；金额计算、去重、执行资格由程序校验。模型返回无证据字段应进入待核对，不能自动补造。

## 6. 记忆治理与权重

当前原型：`关注权重 = 重要性基础分 + 30 × exp(-距发生日天数 / 30)`。投资事项与大额自述基础分 60，其他候选 20。试用阈值为 1000 CNY / 200 USD，仅决定提醒，不是风险评级、认证强度或交易限额；两币种阈值没有兑换含义。

这不能替代事实可信度：一条未经核对的大额猜测，不能压过有凭证的旧记录。当前待核对条目不进入记忆摘要，也不参与财务合计。

正式版还需要：

- `event_time / recorded_at / valid_from / valid_until / source_ref / verified_at / supersedes_id`。
- 新的现金快照替代旧快照；买卖事件在流水中保留；新计划不能覆盖已成交事实。
- 记忆的新增、更正、遗忘由用户可见；个人偏好与逐笔流水分库存储。
- 用户隔离、授权范围、保存期限与导入对账；禁止仅凭提示词隔离用户。
- 大额权限由既有风控确定；记忆的新旧、情绪和模型置信度不得放宽权限。

## 7. 跨场景风险与情绪价值

当前人民币估算公式：

`月初可用现金 + 已记录收入 + 投资流入 - 生活与订阅支出 - 投资流出 - 待执行流出计划 - 本月剩余必要开支 - 应急预留`

月初现金不是今天余额；剩余必要开支不能把已记支出再算一遍。可选计划在界面更正或删除后重算。收入计划不提前计入可用钱。缺项时显示需要补充，外币存在时提示尚未折算。该估算不是银行余额，也不能作为自动交易许可。

正式风险规则还应包括：账单到期日与收入日的时间错配、锁定资产不能当活期、信用卡债务、订阅周期、手续费和税费、重复计划、已有待审批动作、行情过期。

用户自己的长期目标允许展示“本月距目标还有多少”，但不能自动将投资不足判定为风险；保障必要生活费和用户设定的预留优先。

“冰红茶自由 / 会员自由”可以作为可关闭的轻量成就，用用户设定的可选预算和实际账单核算，不能诱导消费或承诺可负担。当前先提供温和文案，没有财富分层。恩格尔系数需要完整统计期和清晰食品口径，零散记录不足以计算或判断生活水平。

## 8. 平台与开源参考

查阅日期 2026-10-17。采用交互和架构思想，没有复制第三方代码，也没有在本项目安装这些依赖。

| 官方平台 / 开源项目 | 学习点 | 本项目采用方式 |
| --- | --- | --- |
| [OpenAI ChatKit](https://developers.openai.com/api/docs/guides/chatkit) | 对话内组件、操作和工具结果可以共存 | 聊天为入口，结构化结果按需展开，动作明确命名 |

这些资料支持实现方法，不代表本项目已拥有相同产品能力。

## 9. 核心 Agent 的学习与评测

“训练核心 Agent”先落到可验收任务：构建经过同意、去标识的多意图例句与标准结构，区分解析错误、工具错误和表达错误。先评估提示词、工具定义、结构化输出与规则校验；只有仍存在系统性失败且有足够标注数据时，再评估微调。

重点样本：口语停顿、纠错、指代、省略单位、中文数字、重复讲述、未成交、转述、假设、美元订阅、退款、券前/券后金额、跨月补记、全仓持仓描述和用户拒绝记忆。

验收指标分别统计：意图召回、金额币种正确率、事实/计划区分率、主体识别、去重误伤、错误入账率、追问数量、工具成功率和未经确认的资金动作次数。高风险漏拦截不能用总体平均正确率掩盖。
