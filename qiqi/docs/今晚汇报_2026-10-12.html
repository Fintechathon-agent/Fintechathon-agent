01结论先行

  • 产品定位收敛为《金融 AI 安全任务台》：银行 AI 智能体，六个场景全覆盖，理财路径做深成可信闭环；评分三块（任务完成率 40% + 安全性 30% + 创新性 30%）没有短板。
  • 演示链已经完整可点：自然语言 → 场景路由 → DAG → 确定性闸门 → 绿黄红权限 → 确认/强验证 → 回执 → 审计回放 → 熔断恢复，公开站今天早上完成最后一轮极简整改并部署上线。
  • 安全不薄：六场景共用一条防线，注入攻击 54/54 拦截、正常表达 0 误伤；金额与限额全部由代码复算，LLM 只解释不生成数字。
  • 诚实口径：能证明的是安全演示闭环，不是生产银行系统：真实身份、真实银行接口、生产隔离仍在集成与验证阶段，所有演示数据均如实标注。

05安全设计（1.5 分钟口径）

一句话：LLM 提建议，Python 把闸门

自然语言→ 闭集场景路由→ 场景 DAG→ 确定性闸门→ 绿黄红分级→ 审计留痕→ 熔断恢复
确定性数字链路（幻觉防护）

金额、余额、限额、卡片状态全部由代码复算；建议价必须与行情/持仓价比对（±20% 区间外即拦）；LLM 只解释结构化结果，不生成数字：没有数字生成权，就没有幻觉空间。

记忆投毒防御（创新主打）

恶意内容写进 Agent 记忆 → 反向污染决策，是 AI Agent 特有的攻击面。三层防御：写入门卫（五级信任分级 + 注入模式检测 + USER/心智模型直写拒绝）、信任只升不降（跨天证据才涨）、读取隔离（spotlighting 定界符标注）。对标 MITRE ATLAS AML.T0080 与 OWASP LLM01。

六场景统一安全框架

一条防线（注入检测）→ 一个路由（闭集）→ 一套权限（绿黄红）→ 一份审计 → 一个熔断器。场景越多，安全代码复用越多，而不是安全承诺变薄；这是与重交互轻内控的同类产品最本质的差异。

分级确认与熔断

绿色查询自动执行；黄色（转账 ≤1000/调额度/取消订阅）用户明确确认；红色（大额转账/挂失/理财动账）验证码 + 人脸强验证。连续 3 次强验证失败 → 锁定资金执行、查询保留、人工恢复，全程审计。

06诚实口径 · 答辩红线（30 秒）

红线：绝不能说的四个词
「已接入真实银行」「已上线」「真实账户授权」「真实交易成功」。 正确说法：演示模拟 · 纸交易仿真 · 待集成 · 集成与验证阶段。
  • 能证明的：安全演示闭环（意图 → 闸门 → 分级确认 → 审计 → 熔断），90 个测试与 54/54 拦截数字。
  • 不能证明的（主动说）：真实身份认证、真实银行/短信/人脸接口、多用户隔离、不可篡改审计、未知攻击泛化、真实用户研究。
  • 数据标注：所有演示数据带 source / as_of / 演示模拟标注，缺少来源或过期数据时 fail-closed——这是合规底线，也是评审看重的诚实。
