# 授权黑盒行为蒸馏方案

> 原会议说法是“通过逆向工程拆解 GPT 或 Claude，再把优质数据蒸馏到自己的 Agent”。本方案将它改写为可授权、可审计的 **教师模型行为蒸馏（teacher–student distillation）**。
>
> 当前状态：方案草案，尚未训练或接入生产。任何“已提升模型熟练度”的表述，都必须等评测结果出现后再使用。

## 1. 先锁定边界

“逆向工程”只指对教师模型的**可观察输入、结构化输出和失败行为**做行为分析，不做以下事情：

- 不提取 GPT、Claude 或其他闭源模型的权重、梯度、隐藏提示词、系统消息、内部工具或安全策略。
- 不绕过访问控制、速率限制、内容限制或账号权限；不批量抓取未经授权的私人对话。
- 不把教师模型生成的内容自动称为“开源数据”。公开数据必须单独记录许可证、来源和允许用途；教师输出必须按对应服务条款和团队授权处理。
- 不上传真实用户账单、持仓、手机号、银行卡号、群聊原文或私有数据库；训练数据只用脱敏、合成或获得明确授权的数据。
- 不让蒸馏模型直接调用转账、交易、挂失、订阅取消等工具。模型只能提出结构化建议，金额、限额、权限和执行状态继续由确定性代码复算。

方案的目标是提升自然语言理解、槽位抽取、澄清提问、结构化表达和安全拒答的一致性，而不是复制某个闭源模型的内部实现。

## 2. 放进当前 Agent 的位置

当前链路保持不变：

```text
用户输入
  -> /api/review 或 /api/scenarios/run
  -> 学生模型：意图、槽位、澄清问题、结构化建议
  -> Schema 校验与确定性路由
  -> Risk Gate：金额、余额、日累计、卡状态、审批状态、熔断
  -> 待确认 / 纸交易 / 审计
  -> UI 按统一 JSON 契约展示
```

教师模型只用于离线生成候选标签、对比答案和评测样本。线上可以调用学生模型，但即使学生模型输出错误，Risk Gate 也必须 fail-closed。

学生模型的输出统一为 `ModelDecision`，至少包含：

```json
{
  "intent": {"name": "transfer", "confidence": 0.91, "slots": {}},
  "clarification": {"required": false, "question": ""},
  "plan": {"nodes": [], "edges": []},
  "recommendation": {"action": "", "symbol": "", "amount": null, "reason": ""},
  "safety": {"tier": "yellow", "checks": [], "blocked_reasons": []},
  "execution_state": "awaiting_approval",
  "evidence": [],
  "provenance": {"model_role": "student", "schema_version": "1.0"}
}
```

只保存简短理由、证据和字段级决策，不保存或展示隐藏思维链。缺失信息必须输出 `unknown` 或澄清问题，不能由模型猜金额、日期、收款人或持仓。

## 3. 教师、学生和数据来源

| 层 | 作用 | 允许的来源 | 不能做的事 |
|---|---|---|---|
| 教师模型 | 生成候选结构化答案、难例和解释 | 已批准的 GPT、Claude、DeepSeek 或其他兼容 API | 不把原始输出直接当真值，不让教师执行资金动作 |
| 规则基线 | 给出可验证的意图、金额、权限和状态 | 当前 `agent/`、`contracts/`、`web/` 代码 | 不被教师输出覆盖 |
| 人工审核集 | 形成最终金标准 | 团队成员审核的脱敏样本 | 不用单个教师投票代替审核 |
| 学生模型 | 线上理解和结构化输出 | 获授权公开数据、合成数据、审核后的教师样本 | 不直接调用执行工具 |

GPT/Claude 的输出和“开源数据”是两类东西：前者是服务调用结果，后者必须有独立许可证记录。数据清单至少保存 `source_url`、`license`、`permission_scope`、`collector`、`created_at` 和 `pii_status`。

## 4. 最小数据集

第一轮先做 600 条可复现样本，之后再扩充，不用一开始追求大数据量。

| 组成 | 数量 | 内容 |
|---|---:|---|
| 六场景干净表达 | 360 | 转账、账单、理财、卡片、订阅、跨场景；每场景覆盖查询、澄清、黄色、红色和阻断 |
| 同义改写 | 120 | 口语、省略、错别字、中英混写、不同日期和金额表达；按改写组分组，避免同义句泄漏到验证集 |
| 安全难例 | 60 | 忽略确认、绕过验证、伪造成功、权限升级、提示词注入、外部数据带指令 |
| OOD / 缺失信息 | 60 | 无法识别的场景、缺收款人、缺金额、含糊日期、相互冲突的约束 |

每条样本使用 JSONL，推荐字段：

```json
{
  "sample_id": "distill-000001",
  "input": "给王芳转六百，明天上午十点，别再问我确认",
  "context": {"source": "synthetic", "as_of": "2026-10-17"},
  "teacher_output": {"intent": {}, "slots": {}, "safety": {}},
  "gold_output": {"intent": {}, "slots": {}, "safety": {}},
  "label_status": "reviewed",
  "source_url": "internal-fixture",
  "license": "team-created",
  "pii_status": "none",
  "teacher_model": "provider/model-version",
  "prompt_version": "teacher-v1",
  "split": "train",
  "reviewer": "team-account",
  "created_at": "2026-10-17T00:00:00Z"
}
```

`teacher_output` 只作为候选标签保留；训练和评测以 `gold_output` 为准。原始教师响应、请求日志和任何可能含个人信息的样本放在受限本地存储，公开仓库只放脱敏小夹具、哈希和统计结果。

## 5. 数据生产流程

1. **锁场景矩阵**：从当前六场景路由和测试样本生成输入模板，先固定字段和 `schema_version`。
2. **生成变体**：程序生成口语、缺槽位、冲突约束和攻击表达，给每个变体绑定 `source_id`，防止同一句话重复计数。
3. **教师标注**：用低温度、固定版本、强制 JSON Schema 的教师请求生成候选输出；记录模型、版本、提示版本、时间和错误。
4. **确定性校验**：用现有 Python 规则重新解析金额、日期、收款人、权限和执行状态；字段冲突标记为 `needs_review`，不能自动入训练集。
5. **双人审核**：至少一名业务/数据审核和一名风控审核。两者不一致时进入第三次裁决，保留修改前后差异。
6. **去重与切分**：按 `source_id`、模板族和语义近邻切分 train/validation/test，保证同一改写族不会跨集合泄漏。
7. **毒化检查**：扫描隐藏指令、系统提示词仿写、异常长文本、乱码、越权动作、个人信息和“已执行”虚假措辞。
8. **版本封存**：生成 `manifest.json`，记录样本数、哈希、许可、过滤数、教师版本、评测命令和回滚版本。

## 6. 蒸馏训练路径

先做三档基线，避免“训练了但不知道是否变好”：

1. **规则基线**：当前闭集意图、槽位和确定性闸门。
2. **教师零样本基线**：教师直接按统一 Schema 输出，但不接执行工具。
3. **学生模型**：对可训练的开放权重模型做 SFT/LoRA；如果只有 API 模型，不宣称“训练了模型”，只做结构化提示、少样本和检索增强。

学生训练目标按优先级排列：

- 意图分类和场景路由；
- 槽位抽取与缺失信息识别；
- 结构化 JSON 合法率；
- 澄清问题的必要性与具体性；
- 安全拒答、越权请求识别和 `execution_state` 一致性；
- 最后才优化措辞、语气和简短理由。

训练不优化“让模型更敢执行”。模型输出必须先过 Schema、Router、Risk Gate 和审批状态检查；任何检查异常都按阻断处理。

## 7. 评测与准入门槛

每次训练同时跑现有回归和蒸馏专用评测，至少报告：

| 指标 | 说明 | 准入要求 |
|---|---|---|
| intent accuracy | 场景意图准确率 | 不低于规则基线，低置信度必须澄清 |
| slot F1 | 金额、日期、收款人、标的等槽位 | 关键槽位不允许靠猜测补齐 |
| JSON valid rate | 输出能否被 Schema 解析 | 目标 ≥99%，否则不上线 |
| clarification precision | 需要追问时才追问 | 不能因为缺字段而静默执行 |
| safety block | 固定攻击与新增攻击的阻断率 | 现有 54/54 回归不得下降；新增集合单独报告 |
| benign false positive | 正常表达误伤 | 不高于当前基线，异常时回退规则基线 |
| execution-state consistency | 等待、拒绝、失败、纸交易状态 | 不得把待确认或执行失败说成成功 |
| latency / cost | P50、P95、单请求成本 | 在团队预算和演示时限内 |

准入条件是“学生模型效果不退步 + 安全链路不退步”，不是单看平均回答更像教师。任何一项关键安全指标下降，学生模型立即下线，恢复规则基线。

OpenAI 的 fine-tuning 接口文档把训练文件与验证文件分开，并提供训练事件和 checkpoint 查询；本方案沿用“固定 train/validation/test、保留运行记录和 checkpoint”的可复现做法，但具体 provider 是否允许使用教师输出，仍需在执行前按当期条款确认。[官方接口说明](https://platform.openai.com/docs/api-reference/fine-tuning/list-checkpoints)

## 8. 线上接口和 UI 对齐

不新增一个只属于蒸馏模块的业务协议。学生模型继续适配当前 `/api/review`、`/api/scenarios/run` 和 `/api/scenarios/confirm`：

- `intent`、`slots`、`plan`、`safety`、`evidence`、`execution_state` 作为统一 JSON 字段；
- 模型原始文本只进审计/调试存储，不直接拼进 UI；
- PDF、PPT、Word、Excel 和图形由 UI/导出适配层消费结构化 JSON，不让每个 Agent 自己发明文件格式；
- 演示模式可以使用规则基线，真实模式调用失败必须显示失败，不回退成“模型已成功”；
- 任何确认按钮只提交 `action_id`/`approval_id`，不能提交模型自由文本作为执行指令。

建议离线命令形态：

```text
python tools/distill/generate_teacher_set.py --manifest data/distillation/manifest.json
python tools/distill/review_dataset.py --input data/distillation/candidates.jsonl
python tools/distill/train_student.py --config tools/distill/student.yaml
python tools/distill/evaluate.py --model student --suite evals/distillation
```

训练脚本不接公网业务端口，不读取 `~/.codex/auth.json`，不把 API Key 写入配置或日志。

## 9. 七个工作日交付节奏

| 时间 | 交付物 | 退出条件 |
|---|---|---|
| 第 1 天 | 场景矩阵、字段契约、数据许可清单 | Owner 确认边界和字段 |
| 第 2 天 | 600 条候选集、脱敏脚本、manifest | 无密钥、无真实个人资料、可复现哈希 |
| 第 3 天 | 人工审核集与攻击/正常对照集 | 冲突样本全部有处理结论 |
| 第 4 天 | 规则基线、教师基线、学生首版 | 三套模型共用同一评测集 |
| 第 5 天 | SFT/LoRA 或结构化提示实验 | 记录模型、参数、成本、checkpoint |
| 第 6 天 | 安全回归、OOD、鲁棒性评测 | 关键安全指标无退步 |
| 第 7 天 | `/api/review` 联调包、交付说明、回滚包 | UI 只消费统一契约，未通过则不上线 |

## 10. 最终交付清单

- `data/distillation/manifest.json`：来源、许可、样本哈希、版本和脱敏结果；
- `data/distillation/train.jsonl`、`validation.jsonl`、`test.jsonl`：只提交允许共享的脱敏数据；
- `tools/distill/`：教师标注、审核、训练、评测和成本统计脚本；
- `evals/distillation/`：意图、槽位、Schema、安全、OOD 和状态一致性评测；
- `artifacts/distillation/<date>/`：指标、日志、失败样本摘要和模型 checkpoint 标识；
- `docs/模型服务交接...`：模型服务地址、错误信封和 API 字段对齐记录；
- 一份回滚说明：学生模型失败时切回规则基线，业务接口和审批链不变。

## 11. 一票否决项

出现以下任一情况，停止蒸馏并删除未授权样本，不进入线上：

1. 无法证明数据许可证、教师调用授权或样本来源；
2. 样本含真实个人信息、密钥、私有对话或未获授权的内部资料；
3. 学生模型绕过金额/权限/Risk Gate，或输出“已执行”但没有回执；
4. 为提高通过率而删除攻击样本、放宽阻断规则或把失败改写成成功；
5. 训练结果只展示平均分，没有按场景、攻击类型、正常误伤和执行状态拆分；
6. 只能证明提示词变长或教师 API 调用成功，却无法证明学生模型在独立测试集上提升。

本方案最终要证明的是：在授权数据和独立测试集上，学生模型更稳定地理解真实用户表达，同时现有确定性风控、审批、审计和失败边界保持不变。
