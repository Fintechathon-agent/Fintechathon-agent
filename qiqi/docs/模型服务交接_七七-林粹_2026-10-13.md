> 交付标准：不是"本地有代码"，而是统一后端能够实际调用，并拿到可核查的模型响应和运行日志。

## 0. 本次同步的关键行为变更（请林粹确认）

1. **新增运行模式**：`--mode demo`（默认）/ `--mode live`（真实模型联调）。
2. **演示模式**：模型不可用或调用失败 → 降级为规则决策，响应里明确标注 `decision_source: "rules"`，不再"静默假装成功"。
3. **联调模式（live）**：只要决策不是真实模型产出的（未配置 Key / 调用失败），直接返回错误信封（HTTP 200 + `status:"error"`，code=`MODEL_UNAVAILABLE`），**绝不回退规则决策**。
4. **审批/执行状态显式分离**：新增 `execution_state` 字段（`awaiting_approval` / `not_executed` / `executed_paper`），"等待审批"不再与"交易完成"混淆；前端文案同步改为"等待审批 / 已执行（纸交易）/ 已确认（未执行）"。
5. **超时核对**：demo 模式 timeout ≤ 60s、max_retries ≤ 2；live 模式按配置原值（默认 timeout=180s、max_retries=3）。前端 `api()` 无自定义超时（依赖 fetch 默认），真实联调时建议前后端统一为 180s。

## 2. 模型配置要求

- 环境变量：`DEEPSEEK_API_KEY`（必填，live 模式）
- 配置文件 `config.fund.yaml`：
  - `llm.base_url`：默认 `https://api.deepseek.com`
  - `llm.model`：默认 `deepseek-chat`（OpenAI 兼容接口均可替换）
  - `llm.timeout`：180（live 原值）/ demo 自动压到 60
  - `llm.max_retries`：3（live 原值）/ demo 自动压到 2
- 模型角色：LLM 只产出建议（proposes）；金额、限额、闸门全部由代码复算（disposes）。

## 3. 请求样例

```bash
curl -X POST http://127.0.0.1:8765/api/review \
  -H "Content-Type: application/json" \
  -d '{"question": "请检查我的持仓健康状况"}'
```

```json
{ "question": "请检查我的持仓健康状况" }
```

- 唯一入参：`question`（可选，缺省走默认问题）。联调时可传具体场景问句，如 `"把贵州茅台全部卖出"`、`"我想再投入 8000 元买基金，但下个月还要交房租"`。

## 6. 界面可见字段（对应队长要求）

| 队长要求 | 响应字段 |
|---|---|
| 输入样例 | `request.question`（错误信封回显）；`intent`（意图与槽位） |
| 模型实际返回内容 | `model_raw`（live 模式透传 LLM 原始 JSON） |
| 拟议动作 | `recommendation.action/symbol/quantity/price/reason` |
| 风控判定及原因 | `gate.passed` + `gate.reasons`（拦截原因） |
| 审批/执行状态 | `queued` + `execution_state` + `auto_executed` |
| 运行编号 | `run_id`（本轮唯一）+ `session_id` |

## 7. 可核查的运行日志

- 服务端：`logging` 输出到 stdout（`python web/app.py > server.log 2>&1`）。
- 审计：`data/audit/` 目录按动作落 JSON（`portfolio_review`、`dag_planned`、`gate`、`dag_failed` 等，含 session_id）。
- 每次 /api/review 的 run_id 可通过审计条目与响应互查。
