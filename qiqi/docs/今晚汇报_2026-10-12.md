## 第 3 段 · 安全设计与数字（约 1.5 分钟）

**口播稿：**

安全是怎么做的？一句话：**「LLM 提建议，Python 把闸门」**。每个场景都走同一条链：自然语言进来 → 闭集场景路由 → 场景 DAG → 确定性闸门 → 绿黄红分级权限 → 审计留痕 → 异常熔断。金额、余额、限额这些数字全部由代码复算，LLM 只做解释，不生成数字——这就是幻觉防护的确定性数字链路。

记忆方面，我们防的是"记忆投毒"：恶意内容写进 Agent 记忆，反过来污染决策。我们的方案是写入门卫加信任分级，USER 层和心智模型层禁止直写，读取侧加隔离标注。这背后对标的是 MITRE ATLAS 的 AI Agent 上下文投毒和 OWASP LLM01。

数字是今晚刚跑出来的：**90 个回归测试全过**；安全评测 **54 条攻击 100% 拦截、20 条正常表达 0 误伤**。

**要点卡：**
- 数字只代表当前本地测试集，不夸大为"未知攻击泛化能力"——这句话被问到就说，主动说更好
- 转账日累计 ≤1000 黄色确认，>1000 红色强验证（tiers.py 唯一权威）
- 熔断：连续 3 次强验证失败锁定资金执行，查询保留，人工恢复

## 附 A · 评委追问口径（Q&A 预演）

1. **「六场景是浅覆盖吗？」** 不是。每个场景都有确定性域闸门：转账有收款人/余额/限额/防重复闸门，卡片有状态机和额度边界，订阅有重复取消闸门。广度是场景数，深度是安全保证，两者不互斥。
2. **「自然语言入口在哪？」** 顶部统一入口一句话路由 + 右侧理财体检输入框。说「你定吧」会拒绝替用户做资金决定。
3. **「创新点是什么？」** 安全纵深：确定性闸门 + 记忆投毒防御 + 五层演化记忆。对标银行内控要求，而不是"更流畅的聊天"。六场景统一框架让安全代码随场景复用。
4. **「记忆到底改变了什么决策？」** 现状：recall 进入决策上下文、reflect 生成心智模型提示、跨场景生日联动演示记忆参与编排。机制化联动（心智模型 → 审批阈值）在路线图，诚实回答。
5. **「安全怎么测的？」** 90 个自动回归测试；54 条入口攻击全拦截；20 条正常表达零误伤。数字只代表当前本地测试集。
6. **「账单数据是真的吗？」** 演示 fixture，界面标注来源。订阅识别（同商户同金额跨 3 个月）和异常规则（大额/境外/深夜/重复/新商户）是确定性规则，接真实数据时口径不变。
