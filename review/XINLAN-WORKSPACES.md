## 本地预览

在本功能分支的工作区根目录启动专用静态预览：

```powershell
node chenchen/scripts/xinlan-preview.cjs
```

浏览器打开 http://127.0.0.1:4318/xinlan/index.html 。该进程只监听本机，固定白名单仅暴露本次页面与已有基础样式；不提供任何 /api 路由，CSP 禁止脚本发起连接。原项目的 node chenchen/server.js 入口不变，尚未加入新页面路由。

若端口占用，可在启动前设置 PORT 环境变量。此版本只做本地预览，没有发布公网。

## 演示路径

1. 普通用户查看风险概况，打开“重复操作已在演示中阻止”，核对模拟说明与下一步。
2. 顶部切换“风控分析员”，在 Case Queue 搜索 DEMO-002，填写至少 5 字意见并提交模拟复核。
3. 切换“风控主管”，重新打开同一案件并记录模拟复核结论。
4. 切回普通用户查看同一事件：复核进展更新，风险仍为“操作已拦截”；标记通知已读。
5. 切到内部 Audit Logs 查看本地记录；管理员预览没有业务复核按钮。

四种角色是演示视角，不是认证账户。不能将页面隐藏、JavaScript 判断或测试里的角色限制当作服务端权限验收。

```powershell

```

结果：55 项测试通过，0 失败；JavaScript 语法通过。新增测试覆盖状态映射、未知状态、模拟复核不覆盖 BLOCK、管理员界面操作限制、重复确认、重置，以及预览文件白名单和拒绝 API/写请求。

浏览器检查使用已有 Playwright 安装，无需修改 package.json。如果工具已在模块路径中，可直接执行：

```powershell

```

支持环境变量 PLAYWRIGHT_MODULE（已有 Playwright 模块路径）、CHROME_PATH（Chrome 可执行路径）、AXE_MODULE（可选 @axe-core/playwright 模块路径）、XINLAN_SCREENSHOTS（截图及报告目录）。这些路径由各开发者按本机设置，不提交机器专属配置。未设置 AXE_MODULE 时不会声称执行无障碍扫描。

本次使用 Chrome，覆盖 375、768、1440 宽度；普通文案、案件筛选/空结果、复核、两端视图同步、错误状态、未知事件、管理员边界、脚本文本安全呈现及重置通过。普通浏览器流程无页面/控制台错误。Dashboard 和 Queue 的 axe WCAG A/AA 扫描通过；axe 在独立测试上下文内关闭 CSP，以允许扫描工具注入样式，应用本身及普通浏览器用例仍启用严格 CSP。自动扫描不等同于全面无障碍认证。

证据见 [浏览器报告](xinlan-workspaces/ui-report.json) 及该目录截图。未测试 Firefox、WebKit、手机真机、真实身份认证、跨用户授权或实际金融接口。
