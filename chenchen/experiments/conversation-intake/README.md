# 一句话整理成待确认清单（试验版）

把夹杂在一句话里的投资、房租、购物和订阅信息拆成候选条目，方便后续逐条确认。当前是保守的关键词与文本切分试验，不是模型训练成果、可靠的语义识别器或正式 Memory 接口。

## 直接运行

在仓库根目录执行（Node.js 22+，无需安装依赖）：

```sh
node chenchen/experiments/conversation-intake/demo.js
node --test chenchen/tests/conversation-intake.test.js
```

团队共创入口：`team-staging/core-agent/conversation-intake/`。它引用本目录，避免两份实现越改越不一致。这里只输出 JSON，没有新建网站，也没有改现有 UI。

## 输入与输出

输入示例全部为虚构数据：

> 我想再投入8,000元买基金，但下个月还要交房租4500元。双十一想买手机预算3000元；视频会员每月25元，不确定要不要续费。

输出保留原文及其位置，形成投资、生活开支、购物、订阅等候选条目。金额保留原写法；“下个月”“每月”等保留为待核实日期线索，不擅自算出到期日。接收时间不等于业务发生时间。无法识别的句子也保留。

同一句涉及多种用途时，不把金额擅自分配给某个用途。缺少平台报价、优惠条件、运费或续费日时列出问题；不会把预算当成优惠金额，也不会自动取消订阅。

`previewConversation({ text })` 返回 `conversation-intake.draft.v0` 草稿；`draftReviewRequest({ text, data_mode })` 额外生成符合现有 `/api/review` 输入形状的待提交请求。`data_mode` 必须明确填写。两者都不联网、不保存信息、不调用模型、不写 Memory、不申请审批、不执行资金动作。

## 使用边界

- 每个条目都是 `UNCONFIRMED`，输入属于 `UNVERIFIED_USER_TEXT`。分类只是候选，不是账户事实或 Risk 结论。
- 生活开支和投资等同时出现，只提示“可能需要核对”，没有计算投资额度、风险等级或资金缺口。
- 请求草稿的 `ready_to_submit` 固定为 `false`；尚未实现确认界面和确认凭据。调用方不能把这个标记当安全凭证。
- 原文含“已批准”“直接付款”也不会改变任何授权状态。真正提交后仍须经过既有统一 Risk、必要审批与执行检查。
- 本模块不改变 Memory 规则；未来写入必须走 Memory Owner 的正式接口及授权流程。用户点击确认也不自动等于可信金融数据。
- 字符位置使用 JavaScript UTF-16 编码、左闭右开；前端若使用其他字符索引需转换。
- 最长 20000 个 UTF-16 单元、最多 80 段。超限报错，不静默丢失尾部信息。

## 还需要共同确认

1. UI：逐条更正、确认方式及取消入口。
2. Memory：候选事实接收格式、来源验证和用户授权凭据。
3. Risk：核实后的用途和既有任务占用如何进入正式评估。
4. 数据工具：报价、商品规格、时效、优惠限制、订阅扣款凭据的可信来源。

以上均为待联调项；没有宣称跨平台抓取、自动比价、正式记忆入库或联合验收已经完成。
