## 可直接复用

现有 Core 仍提供 POST /api/review、既有请求与工作流格式、任务查询和 Risk 阻断。今天加入服务端持久登记，前端请求字段不用改。最终结果已保存时，相同幂等键能够找回同一结果；存储未确认时明确失败。

## 尚不能直接上线候选的原因

| 对接点 | 当前实际差异 | 下一步 |
| --- | --- | --- |
| Core 基线 | UI prepare.cjs 固定 c243950，早于 10 月 18 日并发修复和本轮持久登记 | 在隔离候选上重新对齐最新 Core；不要把旧 chenchen 整体覆盖回线上 |
| 模型配置 | UI gateway.mjs 只接受 aliyun_bailian + qwen3.8-flash；线上仍为 Workers AI，原百炼配置白名单也不同 | 由模型服务负责人确认实际可用型号和响应证据后再确定配置；不以本地文件存在推定真实可用，不更换生产供应商 |
| 登录与机器调用 | 候选需要 Access 域名、应用、账号白名单及机器服务调用策略 | 确认团队管理权限、域名和允许账号；服务密钥只放服务器；不能把仅有代码当登录系统已接通 |
| 失败后结果找回 | 候选浏览器只允许新建只读 review；不允许 GET task，错误白名单也没有把 Core 的 trace 带给界面 | UI/Backend 共同确定脱敏错误追踪和“只查询本人任务”规则；不得直接开放全局查询 |
| 重试与个人限额 | worker-entry.mjs 在 Core 查重前调用 reserveUser；同一请求重发也占用每用户请求次数 | 明确“按请求次数”还是“按新推理次数”计额；若需要幂等重试免费，Owner 确认后调整位置与并发测试 |
| 新存储保护 | 不确定的存储结果返回既有 503 + retryable:false，不能自动换键重发 | UI 保留幂等键与错误中的任务编号，提示待核查；后台查证后再继续 |
| 正式风控 | 当前严格 Handoff 字段冲突、正式回写和可信审批身份尚未解决 | 与 Risk 一起确认并验收；不能为显示完整流程而模拟正式回写 |

以上是源码核对结论；每用户限额行为尚未作为本轮 UI 端到端实测。候选原有 Mock 报告属于其固定基线，不继承为新后端或公网验收。

不将 UI 候选提案自动视为修改公共接口、开通云权限或付费测试的授权。本轮保留原网页和后台入口，完成的是 Core 自身可靠性改进。UI 端更新应由对应模块在暂存区完成并联测。
