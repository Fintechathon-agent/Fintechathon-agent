# Core Agent 旧入口接入与审计交付 · 2026-10-19

这轮重点补上团队旧入口的重试保护，并让任务记录可以直接用记事本查看。旧代码、旧网页和前几轮测试证据保留；没有改其他模块、Memory 规则、Risk 规则、冻结公共 Schema 或正式交付区。

## 已完成的核心接口与工具

| 问题 | 现在的行为 |
| --- | --- |
| 旧入口收到重复请求标识，转换时却丢掉 | 标识进入统一流程。同一操作连续发 6 次，模型替身调用从 6 次降到 1 次，任务编号保持相同 |
| 模型返回但保存失败，旧入口重试再调一次 | 保留原登记和任务编号，503 明确不可自动重试；重启后也不重新调用 |
| 同一标识换金额、问题或会话内容 | 409 拒绝，不能借旧任务的审查结果处理另一件事 |
| 问题超过 20,000 字符时截掉后半段 | 422 明确要求缩短输入，不悄悄丢掉末尾房租、学费等资金约束 |
| 日志不便给队友检查 | 离线导出 TXT，列出模型、风控、审批、模拟结果及事件；同时生成文件校验清单 |

运行修复位于 `integrations/legacy-review-adapter.js`，仅保留已有 idempotency_key 映射并去掉静默截断。没有重新定义公共字段；新入口、会话归属、Memory 授权和执行条件不变。`Idempotency-Key` 是一次操作的重试标识，不是用户身份凭证，不能替代登录和访问控制。

导出工具读取 `GET /api/review/task/{task_id}` 的完整 JSON。默认不带自由文本；加 `--include-content` 才包含原输入和模型回答。它检查任务编号是否一致、提议哈希是否变化、执行前是否有 Risk 与必要审批、回执是否声称真实副作用等；发现不一致时明确列错，退出码 2，保留可读报告。

一次性签名密钥只存在试验进程内，不放入日志。正常模拟案例验证了两类身份签名检查，但 HMAC 仅证明持有该测试密钥，不证明真实审批人身份。401 请求的拒绝由请求/响应记录证明，未额外写进该任务的业务事件表。离线报告也不会重新验证签名或认定输入文件是真实服务器日志。

证据时间戳为 UTC；报告日期按北京时间，2026-10-18T17:xxZ 对应 10 月 19 日凌晨。TXT 与原 JSON 在证据目录使用固定字节存储属性，避免 Git 的 Windows 换行转换破坏文件校验值。

5. **团队展示：先用以上虚构 TXT 核对证据，再安排正式联合验收。** 本轮没有完成真实语音识别、平台实时比价、正式多格式转换、视频或 PPT，相关原型继续保留。
