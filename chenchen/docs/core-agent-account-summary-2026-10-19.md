# 账户汇总接入与测试 · 2026-10-19

本轮补上“只有资产汇总截图时怎么办”：先核对数字，明确缺少的资料，再携带原始依据进入现有审核链路。结果不能直接当完整持仓或投资额度。

## 完成的接口与行为

独立实现位于 [账户汇总实验](../holdings-intake/experiments/account-summary-v1/README.md)。没有修改现有网站、生产 Worker、公共 Schema、其他模块源码或正式交付区。

| 输入或情况 | 处理结果 |
| --- | --- |
| 初始资产、总资产、页面盈亏 | 以整数分核对，明确出入金等口径尚未证实 |
| 页面收益率 | 按页面小数位检查简单资产变化率的四舍五入；不替代收益率算法 |
| 总资产减可用资金 | 保留为未分类差额，不伪造持仓 |
| 创建日期、创建天数 | 不转换为快照时间，不认证当日收益 |
| 不一致、亏损、零基数、格式错误 | 分别提示差异、处理负数、标为无法验证或拒绝非法输入 |
| 只有汇总、没有账户或资金用途证据 | 生成只读候选，等待补充；不生成资金计划或记忆授权 |

候选请求复用 `model-review.v1`，字段放在 `context.account_summary_candidate`，不新增公共状态。截图输入仍为未验证的调用方资料；`memory_consent=false`、`allow_rule_fallback=false`、`action_parameters={}`，不伪造持仓快照编号或已确认的资金计划。

## 验证进度

人工核对并转录用户提供的截图，原始数据完成两条本地后端路径和 20 次请求/响应断言。数据及报告只存本机，不进入团队或个人 GitHub。没有自动 OCR，也没有真实账户连接。

公开复现使用独立虚构数据：[原始请求、响应及核对结果](core-agent-account-summary-evidence-2026-10-19/verification.json)，[中文测试说明](core-agent-account-summary-evidence-2026-10-19/测试说明.txt)。补资料与拒绝两个路径均确认：

1. 数字与来源标签进入模型请求，并随同一 task/request/run/audit 和提议指纹进入 Handoff。
2. 重复请求复用原任务，不再调用模型；未签名的 Risk 回写被拒绝。
3. 正式 Risk 服务未配置时派发返回 503，保留阻断。
4. 测试 Risk 要求补资料或拒绝后，可信测试审批也不能绕过状态；模拟返回 409，无成交回执。
5. 重建内存服务对象后可查原记录，并导出 TXT 审计。仅为对象重建，未证明进程恢复或云端灾备。

模型为固定响应替身，Risk 为本地签名测试判定，不是对截图风险等级的真实评估。每次验证 2 次替身响应、外部模型与付费请求 0。既有正常审批→PAPER 路径继续由原 Golden Path 回归覆盖。

新增 9 项回归，全量 **258/258 通过**，失败/跳过 0：[完整测试日志](core-agent-account-summary-tests-2026-10-19.txt)。[JavaScript 语法检查](core-agent-account-summary-checks-2026-10-19.txt)通过；[既有严格 Handoff Schema 校验](core-agent-account-summary-contract-2026-10-19.json)通过，没有放宽公共 Schema。测试通过代表本地代码验证，不代表真实模型、正式 Risk、审批身份和执行网关已经联合验收。

## 仍需对齐

- 数据来源提供方：汇总口径、持仓明细、真实快照时间、出入金与冻结资金说明；不能只补截图文件名。
- UI：确认“资料待补充”的展示与用户逐项核对方式；本轮未修改 UI。
- Risk：确认候选 context 的读取方式及正式回写地址/签名；Core 不代定风险规则。
- Backend/身份管理：落实受保护入口和可核验的审批身份；邀请管理云账户不等于用户登录与业务授权。
- 模型服务：配置与测试预算确认后再验证真实响应及供应商日志；当前继续零付费测试。

当前只在临时共创入口交付；正式区需 Owner 确认后进入。旧版本、旧证据和既有部署全部保留。
