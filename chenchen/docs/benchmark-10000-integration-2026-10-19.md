## 修复内容与旧记录兼容

问题根因在 Core Agent 内部请求指纹：直接对对象序列化后计算摘要，导致“先写金额再写币种”和“先写币种再写金额”结果不同。HTTP 请求得到 409，无法按原任务重试。

本轮只修改 `integrations/review-workflow.js` 与 `integrations/review-reservation.js` 的请求指纹与匹配逻辑：

1. 计算新请求指纹前，按键名整理 JSON 对象，递归处理嵌套对象；数组的顺序、数值、字符串、布尔值及 null 保持原义。
2. 成功任务、失败任务和持久请求登记使用同一套匹配方法，不增加第二次模型调用。
3. 保留对旧版原始摘要的精确匹配。旧任务按原请求重试仍可用，未完成的旧登记仍返回 503 并拦截；不丢弃字段来“猜测匹配”。
4. 新增 4 项定向回归，修复前 2/4，修复后纳入完整回归全部通过。验证原请求、字段重排、真正改金额、数组重排、字段类型改变，以及旧资金任务和未完成登记。

兼容范围有边界：历史记录只有旧摘要时，原请求可精确重放；不能承诺旧记录也支持任意字段重排。历史任务与既有审批、回执不重写。公共字段、Risk 提案哈希和签名算法保持原样；Memory 规则与 Quant 实现未修改。

## 当前交付边界

本地实际执行 Core Agent/Worker 代码，模型、Risk、审批服务身份和账户数据均为替身或合成值；外部网络请求、真实模型和付费调用均为 0，没有模型训练。并发是受控异步交错，存储故障是内存注入及同进程服务对象重建，不代表 Cloudflare 生产宕机、手机端或公网负载已验收。

本轮没有部署生产，也没有新增真实系统接通或联合验收证据。正式 Risk 服务、可信用户身份、执行网关和真实模型/账户数据仍需团队提供并联调确认。保存状态不确定时继续阻断，不将“安全拦截”描述成“已自动恢复”。代码和报告进入 `chenchen/` 与临时共创入口；正式交付区和其他成员目录未修改。
