## C. 需要其他模块配合解决的阻塞

### 1. 来源任务字段的位置未锁定一致

Core 输出的风控交接包顶层有 `source_task_id`，而 `risk-handoff.v1` 的严格 Schema 未声明它。当前导出包会被遵守 Schema 的接收端拒绝。本次使用全新本地任务、AJV 8.17.1 完整验证，仍复现该问题；没有删除字段或放宽 Schema 伪造通过。

Core/Backend 与 Risk 需要共同选定并记录以下之一：

- 保留现有顶层字段：用双方认可的版本变更补齐 Schema、样例及兼容校验。
- 以已有 `reviewed_input.source_task_id` 和 WorkflowRecord 来源字段为标准：确认消费者完成迁移后，再移除交接包多余的顶层别名。

本轮不替双方做决定，也不把现在的包标成“符合冻结协议”。

### 2. 模型回执编号要求不一致

Core 允许供应商未返回编号时记为 null；当前 Risk 校验要求真实且非空。测试已经证明会拒绝。本轮没有编造编号或放松对方校验。需模型服务提供方确认实际返回字段，并与 Risk 确认可核查证据的接受标准。

### 3. 正式回写和身份仍未接通

目前 Risk 的沙盒记录与 Core 任务通过来源编号关联。Risk 沙盒成功后，Core 仍为 PENDING_RISK；没有伪造 Risk 回调让 Core 显示完成。需 Risk 提供正式接收地址与回写服务，Backend 提供可信审批身份，双方联合跑正常、拒绝、超时、重复、改参、撤回和恢复。签名密钥仅放服务器。

### 4. 真实资料和模型验收尚缺前提

需要数据模块提供经授权、可追溯的余额与账单样例；Memory 提供既有授权规则下的引用。Core 不把用户随口输入或外部文本变成可信账户、长期记忆或执行许可。百炼尚未开通且当前未授权付费，本轮未切换线上模型，也未进行付费测试。
