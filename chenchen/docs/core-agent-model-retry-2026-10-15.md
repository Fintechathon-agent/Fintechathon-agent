# Core Agent 第二轮：短暂故障可以恢复，安全边界不放松

## 用通俗的话说

模型偶尔临时不可用时，系统在同一项任务内自动再试一次；仍失败就停下。不会把失败伪装成成功，也不会为了演示通过跳过 Risk。网页结构不变，重点补后端可靠性。

## 已完成接口及行为

- `/api/review` 请求不变。重试保持 task_id、request_id、run_id、audit_id 一致，输入和动作参数不变，不新建多份任务。
- 成功响应：`model.model_response.attempt_count` 为尝试总次数，`retry_count` 为重试次数；一次成功是 1/0，失败后重试成功是 2/1。
- 最终失败响应：HTTP 非200，`workflow.status=MODEL_FAILED`；计数位于 `workflow.model.response`。按 task_id 查询时响应直接是 workflow。
- 成功、失败两种情况下，顶层 `audit.events` 都保存重试事件。Risk Handoff 的 `model` 对象可带同样计数。旧记录省略新字段，不能据此假定过去调用过几次。
- 默认总尝试2次，服务端最多3次；`MODEL_MAX_ATTEMPTS=1` 可关闭重试。非整数/无效配置回到默认2次。
- `MODEL_TIMEOUT_MS` 现在是全部尝试和退避共用的总预算，当前部署45000ms。默认退避250ms，第三次前500ms；HTTP上游 Retry-After 更长时遵守它。如果等完已无法在预算内尝试，则不再重试。
- 时间耗尽立即失败；Workers AI 迟到结果不能改变已失败的任务。模型推理不执行资金动作；底层推理在超时后未必能取消，因此不把它称为“已取消供应商请求”。
- 公网禁止规则降级保持不变。模型成功后仍等待 Risk 和必要审批，真实执行始终关闭。
