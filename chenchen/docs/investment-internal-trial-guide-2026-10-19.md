# 投资助手内部试用指南

先看“识别到了什么”，再核对，再看是否需要补资料。通过风控和审批后也只生成 PAPER 模拟记录，不能当真实成交。

## 这次怎么试

下载仓库，需要 Node.js 22+。在仓库根目录运行：

```powershell
node chenchen/experiments/life-planning-v1/server.js
```

打开本机 [合成演示记录](http://127.0.0.1:4181/fixture)。它是本地 JSON 联调演示，不是发给其他人即可访问的网站；其他成员需要自己启动。若端口已有服务，先核对是否旧版，由运行者停止旧进程后再启动。

在另一个 PowerShell 终端，可发送一条虚构小额请求：

```powershell
$sampleBody = @{ text = '我今天餐费花了.59元；我不想买基金900元；我申请取消会员25元。'; data_mode = 'SYNTHETIC_REPLAY' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:4181/api/life/v1/intake' -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($sampleBody))
```

应该看到 `.59元` 完整保留，“不想买”是 NEGATED（否定），申请取消是 CANCELLATION_REQUESTED（申请中）。不应该出现已买入、已扣款或取消成功。金额只是待核对的原文，不自动记入真实账本。

## 团队按这五件事验收

1. 只有汇总截图：解释能核对的数字，列出持仓明细和更新时间等缺项，不凭差额生成持仓。
2. 说不想买、只是举例或朋友的情况：检查原文分类，不得生成本人已授权动作。
3. 投资可能占用房租、学费：查看已确认的用途和可用资金；余额不够或多个任务重复占用时应阻断。
4. 等待风控、等待审批、已拒绝、批准过期或批准后改金额：都不能直接模拟执行。模型故障要显示失败。
5. 正常合成路径：检查同一个任务编号下的模型提议、Risk 判定、审批和无副作用模拟回执，最后查看审计。

批量复跑方法与已有结果见 [1000 例说明](investment-benchmark-1000-2026-10-19.md)。不要把虚构数据测通说成真实模型或正式风控接通。

## 截图比价当前怎么准备资料

可先逐项人工转录三份截图：同一商品/套餐、规格与份数、商品价、配送费、其他费用、优惠券门槛、是否满足条件、报价时间和有效期。优惠未知就待确认，不按最大优惠计算。这里只提供“已知报价中最低”的比较，不保证全网最低，不自动下单。自动上传识图尚未实现。

## 发现问题怎么记

记录版本、虚构输入、预期、实际结果、出现时间，以及接口返回的 task_id/request_id/error code。可以使用本地 TXT；不需要提供密码、密钥、真实账号或聊天记录。真实用户资料先按明确授权和脱敏流程处理，不直接放 GitHub。

Cloudflare 上的现有 `/api/review` 与本地 `/api/life/v1/*` 是不同入口；本轮修复尚未接入线上页面。公网健康正常不代表真实 Risk、审批身份或完整资金业务可用，公测前仍需验收这些环节。
