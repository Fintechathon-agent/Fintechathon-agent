# 风险、确认与执行：实际实现架构

```mermaid
flowchart TD
  U[用户输入与明确画像确认] --> S[本机会话与 CSRF 校验]
  S --> H[原有 Core Harness / Financial Tools]
  H --> I[investment-agent.v1 原始交接]
  I --> T[服务器任务存储与版本绑定]
  T --> R[Risk Engine / PLAN_REVIEW / R01—R07]
  R -->|BLOCK 或 ERROR| STOP[展示全部原因，暂停相关执行]
  R -->|ALLOW 或可接受 REVIEW| A[逐项接受风险 + 确认完整计划]
  A --> G[Action Gateway 读取服务器记录]
  G --> J[可靠写入执行前审计]
  J --> P[EXECUTION_PREFLIGHT / R01—R10]
  P -->|缺权限、无有效确认或检查失败| STOP
  P -->|满足执行资格| K[原子持久化幂等占用 RUNNING]
  K --> E[按步骤复核 + 原有 Paper Trading 工具]
  E -->|可信回执| OK[持久化模拟结果 / 成功审计]
  E -->|异常或回执不明| UN[UNKNOWN / 核查，不自动重试]
  OK -->|用户事先同意| M[原有 Memory 接口]
  G -->|同一计划重复请求| OLD[返回已有结果或未知状态]
  T -->|相关版本改变| INV[原确认失效，重新检查与确认]
```

三条状态线独立：

- 风险：`ALLOW / REVIEW / BLOCK / ERROR`；REVIEW 原因接受后仍保留。
- 确认：`UNCONFIRMED → CONFIRMED / REJECTED`，确认后可 `REVOKED / INVALIDATED / EXPIRED`。
- 执行：`NOT_STARTED → RUNNING → SUCCEEDED / UNKNOWN`；调用工具前异常为中止，恢复时先核查持久化状态。

**代码对应：** `engine.cjs` 计算规则；`gateway.cjs` 验证确认和控制执行；`store.cjs` 持久化与审计；`core-adapter.cjs` 适配队友数据和工具；`server.cjs` 提供受保护 HTTP 入口。正式部署需队长统一这些模块的调用边界。
