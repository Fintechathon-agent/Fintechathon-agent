# 第四板块：最小风控引擎与执行网关 v0.1

状态：可运行的**本机虚构数据集成版本，待团队评审**。实现位于 `modules/safety-risk-eval/`；接口草案沿用 `docs/safety-risk-eval/contracts/`。没有真实投资操作权限。

## 一、本轮完成的链路

团队 `chenchen/core/harness.js` 健康检查 → 现有 `investment-agent.v1` handoff → Risk Engine R01—R10 → 逐项风险接受与完整计划确认 → Action Gateway → 原有 `financial-tools.paperTrade()` → 持久化模拟结果及审计 → 用户同意后调用原有 Memory。

集成服务复用队友原有 Harness、工具与投资组合页面，通过第四板块适配器连接；未修改 `chenchen/` 或七七的源代码。启动本模块后，`/investment` 是原页面，完成健康检查后会出现“进入风控审核”链接；`/risk` 是完整的审核与执行演示页面。原先独立启动的 `chenchen/server.js` 仍保持原状；团队正式部署需由架构负责人决定启用本集成入口或迁移其路由。

## 二、运行与检查

仓库根目录运行：

```sh
npm --prefix docs/safety-risk-eval/contracts ci --ignore-scripts
npm --prefix modules/safety-risk-eval start
```

打开 `http://127.0.0.1:8780/risk`。`RISK_PORT` 可改端口，仅监听本机。浏览器身份是服务器生成的本机演示会话，不是正式账号认证。

```sh
npm --prefix modules/safety-risk-eval test
npm --prefix modules/safety-risk-eval run eval
```

`eval` 重跑实现测试、29 项草案契约回归和 4 项队友原有契约回归，产出 `eval-results.json`，含测试数量与源文件摘要。浏览器脚本为 `modules/safety-risk-eval/scripts/browser-check.cjs`；需本机可用的 Playwright 和 Chromium，可通过 `CHROME_PATH` 指定浏览器，通过 `RISK_BASE_URL` 指定已运行服务。浏览器结果保存为 `browser-results.json`。

运行状态只保存在被 Git 忽略的 `modules/safety-risk-eval/.runtime/`，其中包括演示会话、方案、审批、输入快照、幂等记录和审计。不要将此目录上传。测试使用独立临时目录。退出服务会释放单写者锁；意外终止后残留的 `writer.lock` 必须先由维护者确认原进程已退出再处理，不能盲目删除一个仍在运行的服务锁。

## 三、固定规则实际实现

| 范围 | 实现 | 主要证据 |
| --- | --- | --- |
| R01 权限 | 可信用户与持仓归属、服务器工具允许范围、真实交易禁止；默认无权限 | `engine.cjs`、HTTP 会话隔离测试 |
| R02 数据 | JSON Schema、版本、证据链、工具来源、候选摘要、估值一致性、样本有效性、过期行情、缺失交易参数 | 四态引擎用例、缺失数据/相关性/订单模型用例 |
| R03 硬约束 | 按步骤复算现金和可卖数量；备用现金、禁止资产、允许资产；中间买入也纳入禁止资产检查 | 资金不足、卖超、伪造可卖量、备用金边界 |
| R04/R05 集中 | 总资产和非现金投资两口径；现金不排名；行业未知独立处理；改善不能加重其他超限 | 双分母、等于上限、改善允许/阻止、未知行业、危险中间步骤 |
| R06/R07 复核 | 历史回撤幅度与用户值比较；同一资产对的相关性及合计权重同时判断 | 历史回撤等于/超过、相关性 ≥0.8 且权重 >0.4 |
| R08 确认 | 整计划、逐原因、用户、检查 ID 与版本绑定；过期/拒绝/撤回/变更不能执行 | 确认失效、拒绝、复核接受、硬阻止不可覆盖 |
| R09 幂等 | 用户范围的幂等键；同计划换键也不再执行；原子持久化占用；结果未知不重试 | 同键/换键、并发、进程重启、超时核查 |
| R10 审计 | 执行前成功追加并同步文件才可继续；输入快照与完整风险字段可关联；结果与异常记录 | 审计失败工具调用为零、成功/中止/未知事件 |

计算比例采用已有工具约 8 位小数的精度，浮点比较容差为 `1e-8`；金额一致性容差为 0.01 元。以上是演示计算约定，非监管数值要求。正式资金系统应使用定点金额和由第三板块确认的交易精度。

Risk 判定保持 `ALLOW / REVIEW / BLOCK / ERROR`。ERROR 优先表达检查不完整，同时保留已发现的 BLOCK；Risk 输出仍 `execution_allowed=false`。网关仅在执行前检查完整、R08—R10 通过、其他原因均为已明确接受的复核时取得执行资格；原 REVIEW 原因不会被抹除。

## 四、客户端不能自报“我已批准”

前端仅能提交任务 ID、当前绑定、逐项接受 ID 和明确确认动作。服务器从自己的任务存储读取持仓、方案、权限和审批；客户端附带 `approval`、`user_id`、`authority` 等额外控制字段会被拒绝。执行路由只接收任务 ID 与幂等键。会话 Cookie 使用 HttpOnly/SameSite，写操作验证来源与 CSRF。

确认有效期目前为 15 分钟的可配置演示值。用户相关约束更新会替换版本并使旧确认失效；无关资料不经过此更新入口。执行开始后不能假称已经撤回或中止。执行失败或回执丢失被保守标为 UNKNOWN，必须由可信执行适配器提供对应执行 ID 与内容摘要的回执才能核查，不提供“用户点击成功即可核销”的接口。

## 五、持久化和审计边界

单写者锁保护同一状态目录。任务与幂等状态通过临时文件写入、`fsync`、原子改名保存；执行前先持久化 RUNNING 占用，再调用工具。重启加载到 RUNNING 时转为 UNKNOWN。JSONL 审计保留前一事件摘要，启动检查链的连续性；每个事件含关联 ID、用户/任务/方案版本及执行或风险内容。

这是本地演示持久化，不是分布式事务、不可篡改审计或生产级授权服务。文件所有者仍可修改文件；文件系统掉电保证、进程异常后维护、权限隔离、审计保留期限与集中存储需要团队部署方案。执行后日志失败不会重放交易，进入 UNKNOWN 核查。

## 六、演示脚本与可见证据

1. 正常持有：确认演示画像 → 健康检查 ALLOW → 确认整计划 → 模拟成功 → 展开审计。
2. 回撤复核：选择“回撤超过容忍值” → REVIEW → 不逐项接受时不能确认 → 接受并确认后可模拟，原原因保留。
3. 硬性阻止：备用现金 11000 元 → BLOCK → 确认与执行按钮禁用；直接请求执行 API 也不会调用工具。
4. 版本失效：先确认，再把备用现金改为 6000 元并重检 → 原确认失效。
5. 重复请求：模拟成功后重发同一请求 → 显示既有状态，审计新增重复请求事件，不新增执行。
6. 数据缺失：选择 B/C → 缺少完整可验证调仓步骤 → ERROR；不编造执行结果。

网页数据来自实际本机服务器与规则代码，不是预录的状态切换。测试和演示都使用虚构资产，不宣称真实账户或市场数据验证通过。
