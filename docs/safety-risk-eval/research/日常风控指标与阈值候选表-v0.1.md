# 日常风控指标与阈值候选表 v0.1

日期：2026-10-17。状态：第四板块研究提案，指标与阈值待用户及团队评审。

来源编号、链接和实际阅读范围见[理财书籍与权威资料研究](./理财书籍与权威资料研究-v0.1.md)。M01—M20 是研究候选编号，不替换 D01—D08 或 R01—R10，也不是已经上线的新规则。

## 1. 先明确“标准”有三种含义

1. **计算标准：** 同一组输入得到同样结果，例如按付款日期算余额。可以先统一。
2. **参考目标：** 预算比例、储备月数等，说明来源后由用户选择；超出参考值通常先给建议。
3. **执行约束：** 用户确认学费不能挪用、硬性最低现金以及权限要求。对具体冲突动作拦截，不能由模型引用书中比例后自行生成。

建议先采用前两类资料完善判断和解释，再由团队确认哪些个人约束实际进入执行检查。

## 2. 所有指标共用的口径

| 项目 | 统一要求 |
| --- | --- |
| 金额与期间 | 单一资金池、币种与截至时间；计算采用整数最小货币单位。存量和期间流量不混算；周、月、学期、年度分别记录 |
| 收入 | 日常预算主要看税后现金；税前收入另列。已到账、预计、一次性和压力假设分开，已包含在余额的工资不再增加 |
| 学生与不稳定收入 | 家庭支持、奖助学金与兼职保留来源、期限、用途。可以另做“可用生活支持”预算，不冒充工资或标准 DTI；借款、赎回、内部转账不当工资 |
| 经济分类与现金支付 | 消费结构按明确的发生口径；付款能力按实际扣款日。信用卡买书与还款不重复算消费；内部转账不创造收入或改变合并净资产 |
| 预留与占用 | 同一学费的预留、账单、冻结、实付需可信关联，只形成一次有效负担；匹配付款消耗其预留，不继续扣原预留 |
| 余额与冻结 | 账面余额和已扣冻结的可用余额分开。已反映在可用余额的冻结不再扣一次；字段净额范围不明确时先对账 |
| 目标与事实 | 按月计提是预算安排，不代表已经存够；未来收入不是当前可用余额，历史收益不是学费保障 |
| 未知及零分母 | 未知不填 0。分母为 0 时显示“不适用／无法计算”并说明原因；数据不足的局部指标不自动拖停无关分析 |
| 合理用途 | 学费、食品等必要支出不能因为比例超参考而自动取消；应急金按其原用途使用可相应消耗预留 |

## 3. 二十个候选检查点

“硬检查”只针对已确认保护范围和当前拟议动作；“提示／描述”不自动变成执行阻止。以下公式是产品可采用的定义草案，注明源于何种方法；没有来源给出统一阈值时明确写无。

| 编号与维度 | 公式、期间或判断对象 | 数值依据及适用条件 | 建议用途与来源 |
| --- | --- | --- | --- |
| M01 新增可安排额度 | 当前可用余额减未被同笔有效占用覆盖的保护预留、尚未反映的占用及不重叠硬性备用额 | 本次本金、必要费用及不重叠额外占用超过额度才构成新增动作冲突；负数保留为已有缺口 | 硬检查；D02、D04。项目会计与确认用途设计，参考 I02、B03，不是书中的现成公式 |
| M02 付款日缺口 | 按真实日期递推现金和占用，检查动作前后各已确认付款时点 | 在选定保护范围内无法覆盖应付金额或其他硬保护；“0”是算术缺口边界，不是经验比例 | 硬检查；D03。I02、I03、B03；日级化和授权关联为产品推导 |
| M03 近期必须支出覆盖 | 某付款日、扣除其他有效保护后的可支付资金／该日到期且未付金额 | 仅此口径低于 1 表示这笔覆盖不足；应付为 0 时不算比率。预计收入需另列情景 | 展示缺口辅助；对应具体动作由 D02、D03 判断，不能只看一个比例。I03、I05 与产品推导 |
| M04 期间现金结余 | 选定期间实际流入减实际流出；同时区分收入、借款、资产变现与账户间转账 | 无统一百分比；正结余不证明期间内每一天都够用，包含借款的正流入不等于收入改善 | 趋势与核对；I02、I12、B03。合并口径剔除内部转账 |
| M05 三类预算占比 | 必要、储蓄与还债、可选三类／同期间到手收入 | I01 的 50%／20%／不超过 30% 为可选经验模板；不是每项必须花满，更不是投资上限 | 提示与自选目标；I01。最低到期偿付与额外还本分别记录，分类约定见表后说明；未统一前不输出完整三类对比 |
| M06 四桶预算占比 | 固定费用、投资、储蓄、自由消费／同期间到手收入 | B08 参考依次为 50%—60%、10%、5%—10%、20%—35%；选择的完整预算必须合计 100%，不能各取上限 | 作为 M05 的替代模板；按作者分类，固定费用桶包含基本食品，不等于会计上的固定／可变费用分类。B08 作者文章 |
| M07 应急储备月数 | 当前未被其他用途约束、及时可动用的应急储备／用户确认的月必要现金支出 | I11 常见 3—6 月；I08、B02 生活支出口径需另标。首版拟选“必要支出”，具体目标由用户确认 | 柔性目标提醒；D06。不稳定收入、扶养责任影响目标；不以低于目标阻止全部必要付款 |
| M08 学费等目标储备 | 剩余缺口＝目标尚需支付额减已可信分配的专款；每期需存＝正缺口／到期前剩余可储蓄周期数 | 无统一金额；周期数为 0 时直接呈现到期缺口。年度费用按月分摊仅用于预算 | 专项规划；I04、I12。学费与应急目标分开；不把“计划存入”当已到账 |
| M09 标准债务收入比 | 全部月度债务偿付额／税前月收入 | I06 定义；未采用通用 36%／43% 硬线。没有税前数据时不冒充标准 DTI | 债务诊断；明确住房按揭等范围，实际借贷准入依相应机构规则 |
| M10 非房贷还款负担 | 每月非房贷信用还款／税后到手收入 | B02 原表经验建议低于 20%；不含住房按揭，不等同 M09 | 提示候选；不将学生教育借款等不同情形直接合成审批结论 |
| M11 全部还款现金负担 | 当期全部到期本息／同期间税后现金收入 | 产品自定义，无已核实的统一百分比；与 M09、M10 分别命名 | 观察还款挤压生活预算的程度，实际付款缺口回到 M02，不直接判授信资格 |
| M12 储蓄比率 | 当月新分配储蓄／当月税前收入，须排除账户间转移旧存量 | B02 原表经验建议 5%—10%；税前分母与税后预算不同，不直接对比 | 提示候选；具体“新分配”计算待定义，不把本月余额总额当本月储蓄 |
| M13 资产负债率 | 同一时点负债／资产 | B02 通用分析公式，无本项目统一阈值；资产为 0 时不除零 | 描述存量和变化；资产估值、债务期限另列，不替代当日付款能力 |
| M14 窗口流动覆盖（改编） | 指定估值时点与窗口，窗口内可用的未受限流动资产／该窗口到期负债 | 参考 B02 流动比率的产品改编；估值、窗口、变现日期与证据另列，没有通用批准线 | 仅描述窗口覆盖；窗口末能变现不代表能付更早的账单，具体日仍查 M02、M03，不冒充教材原版比率 |
| M15 净资产 | 同时点资产减负债 | B02、B03 通用公式；不设统一正数最低线 | 描述；负值不等于法律上的破产，房产／基金市值不等于可花现金 |
| M16 收入稳定性与压力情景 | 固定／浮动／一次性来源、到账记录、来源集中；另算工资延迟或减少时的缺口 | B03、I10 支持观察维度，没有验证过的统一概率或权重。情景强度需标明假设 | 提示、询问与对比；情景缺口不是“将必然发生”，不能靠情景收入解除当前硬阻止 |
| M17 资金期限与变现匹配 | 对比保护用途用款日，与产品可靠的最晚可用日期、费用及波动风险 | I09 给短期目标风险教育；实际日期须第三板块核实，不能把 5 年建议改成全部产品的禁投期 | D07；已知保护用途不足可阻止，规则未知则补资料，不编造赎回保障 |
| M18 食品烟酒消费占比 | 同期间食品烟酒支出／同口径消费总支出 | C03 统计结构口径，无个人投资批准阈值；消费为 0 或分类不足不计算 | 描述与趋势；不是食品／工资，学费集中月和家庭结构会改变结果 |
| M19 家庭责任与保障核查 | 必要扶养义务、已有保障范围和已确认保费付款；未知只列待核实 | B09、B10 的目录只支持补读方向；C04 支持综合考虑，未核得通用保费／收入比例 | 问卷与解释候选；不以“保费不足 10%”直接判不合格，不索取无关健康隐私 |
| M20 预算与实际偏差 | 同类别实际发生额减预算额；如显示比例，分母必须是该类别预算而非工资 | B02、I12 支持跟踪和核对；预算为 0 时显示超出金额，不输出无穷比例 | D05 柔性提醒；区分已发生消费与新增计划，不自动把投资归入订阅预算 |

M01 衡量新增、未被原预留覆盖的可选安排；M03 衡量某笔账单能否支付，二者不能互换。由可信支付服务确认可用于该笔结算的同用途冻结，可在该笔付款分子中计入一次；金额已经包含时不再加回。未知用途、不可结算的冻结不算可支付资金。

三类预算的分类须单独评审：I01 的简表将房贷／房租列入必要支出、信用卡付款列入储蓄与还债，但未解决所有最低还款与额外还本细节。一个**待确认的改编方案**是将必要的最低到期偿付归入必要支出，将额外还本与储蓄归目标类别。若采用，必须标为改编模板，不能声称与原表分类完全相同；两种模板不混算，同笔债务只映射一次。

## 4. 三套模板可以比较，不能同时强加

| 模板 | 使用方式 | 首版建议 |
| --- | --- | --- |
| 实际金额与付款日 | 用户确认学费、房租、生活费、已有占用和可用现金 | 优先统一，直接回答“会不会影响生活安排” |
| 三类预算 M05 | 选择期间、到手收入和单一分类，比较实际占比与参考目标 | 提供解释；不强制新用户达标 |
| 四桶预算 M06 | 将储蓄与投资分别列出，选择合计 100% 的分配 | 后续可选；不与三类模板叠加计费或重复扣款 |

4321、房贷三一、保险双十及按年龄分配风险资产的经验法已记录在研究文档。由于适用对象、分母或产品细分不足，本轮不将它们参数化；可作为队内讨论不同方法的对照。

## 5. 建议的首版处理标准

| 情况 | 结论及显示内容 | 能否通过勾选继续 |
| --- | --- | --- |
| 已确认学费等保护用途被本次新增投资占用 | `BLOCK`：用途、缺口金额、付款日、降低或延后计划的方法 | 不能用“接受风险”覆盖；改变用途需独立确认并重检 |
| 必需余额、费用、日期或变现证据缺失 | `REVIEW`：明确缺什么及谁提供 | 不能勾选跳过证据；与本次无关的可选指标可继续显示未评估 |
| 预算比例／柔性储备目标未达参考 | 提示或可接受类 `REVIEW`，是否进入总体结果由团队统一 | 可以明确接受柔性提醒；不得覆盖同时存在的硬冲突 |
| 必要计算、账本或授权校验服务失败 | `ERROR`：检查未完成、暂停相关动作 | 不能回退预置成功；服务恢复后重检 |
| 信息充分且已评估范围无冲突 | 相应规则 `ALLOW`，显示范围与依据 | 仍需其他风险检查及有效确认，不代表交易完成 |

没有 `ERROR` 时按 `BLOCK > REVIEW > ALLOW` 聚合并保留所有原因。有 `ERROR` 时不得显示整体检查完成，已有硬冲突也保留。研究指标不自行改写正式共享接口；正式枚举与映射由架构 Owner 统一。

## 6. 用例：检查这些标准是否会误导用户

以下均为虚构、可手算的文档验收例子，不是已运行的程序测试。

| 用例 | 输入与口径 | 应得到的解释 |
| --- | --- | --- |
| T01 保护学费 | 当前现金 12,000，已含工资；学费 6,000、房租 1,500、生活费 2,500 均确认未付；无额外占用，演示费用 0；拟投 8,000 | M01 可新增安排 2,000，本次多用 6,000，阻止该投资；2,000 不是推荐投资额 |
| T02 正常缴学费 | T01 资金安排，按可信账单支付原学费 6,000 | 支付后现金 6,000、剩余保护 4,000，可安排仍 2,000；不能因“自由额度小于学费”误拦 |
| T03 预留转冻结 | T01 学费预留 6,000 转为同笔有效冻结，尚未实付；账面 12,000、已扣冻结的可用余额 6,000 | 账面 12,000−冻结 6,000−其余保护 4,000＝2,000；等价于可用 6,000−其余保护 4,000。不能再扣原学费预留；该冻结可否交学费另核可信结算状态 |
| T04 月底结余但日期缺口 | 20 日须付学费 6,000，20 日可支付现金 4,000；工资 8,000 预计 25 日到 | 20 日缺 2,000；月底可能为正不能覆盖该缺口。预计工资不充当今天余额 |
| T05 必要支出高于参考 | 月到手 8,000，必要支出 5,000，占 62.5%；本例无债务，必要付款及用户硬性预留均有可信资金覆盖 | 提醒预算压力，不仅因高于 50% 禁止支付房租、学费；其他风险另查 |
| T06 储备与学费不重叠 | 现金 12,000，其中学费专款 8,000，剩余 4,000 专门用于应急，无其他预留；月必要支出 2,000 | M07 为 2 个月，不是 6 个月；是否提高目标需讨论，不把学费加入应急分子 |
| T07 零工资学生 | 工资明确为 0，有已到账且用途确认的学费／生活支持；账单金额和日期均已知，其他适用税前月收入尚未提供 | 不生成以工资为分母的比例；标准 DTI 缺少税前总收入资料不计算，若适用收入确认为 0 才标零分母不适用。家庭支持不自动算工资，付款仍按余额和用途判断 |
| T08 分母不同 | 税前月收入 10,000、到手 8,000；月房贷 2,000、其他信用还款 1,000 | M09 为 30%；M10 为 12.5%；M11 为 37.5%，三个指标名称和范围分别展示 |
| T09 目标积累 | 8 周后学费 6,000，已有专款 2,000；每周均有一次可存入机会 | M08 还差 4,000，每周计划 500；若实际未存入，不显示“已备齐” |
| T10 储备目标与付款用途 | 用户应急储备目标 6,000，现有 5,000；发生已确认应急用途付款 | 目标不足先说明；匹配用途消耗对应储备，不能因低于柔性目标拦住必要付款；现金和其他硬保护仍检查 |
| T11 信用卡与内部转账 | 买书 500 已记消费；随后还卡 500；本人账户间另转 2,000 | 消费结构仍 500；还款日现金流记录 500 扣款；内部转账不新增收入或消费，付款账户可用性另查 |
| T12 学费月度分摊 | 年度学费 12,000，预算分摊每月 1,000，但下周一次应付全额，当前专款只有 4,000 | 不用“本月预算 1,000”替代下周实际 12,000 的付款；现金到期缺口单独计算 |
| T13 食品比例不是许可 | 食品烟酒 1,200，消费总额 4,000，比率 30%；拟投资仍影响已确认房租 | 不依据 30% 判安全；房租冲突继续拦截。不能把食品／收入称为同一统计指标 |
| T14 比率或账户未知 | 当前余额服务失败；或某个非必要的消费分类缺失 | 前者 `ERROR` 暂停依赖动作；后者只标 M18 未评估，不编造数据、不无故停止其他可完成分析 |
| T15 窗口够用仍有日缺口 | 今天现金 1,000，另有 4,000 经核实两天后可用；窗口为本月、仅有明天应付 3,000 的一笔负债 | 窗口覆盖虽大于 1，明天仍缺 2,000；M14 不能覆盖 M02 的日期判断或签发执行许可 |

## 7. 为以后统一数据格式保留的最小信息

这是需求清单，不是已发布的接口；不得把新增字段直接塞入不允许额外属性的现有 Schema。

| 信息组 | 需要记录什么 |
| --- | --- |
| 指标定义 | 稳定编号、定义版本、公式、期间、币种、分子／分母范围、包含与排除项 |
| 参数依据 | 来源编号及链接、章节／页码、查阅日期；教育建议／用户配置／产品规则分别标记 |
| 事实输入 | 来源与截至时间、原始回答和归纳分开、到账状态、用途、日期、去重关联、可信级别 |

## 8. 下一轮如何取舍

1. **先统一 M01—M03、M08、M17 的实际金额和日期口径。** 它们最直接保护工资、学费、房租等用途。
2. **再确定 M07 的必要支出清单和柔性储备目标。** 同时区分学生、稳定工资、不稳定收入、有扶养责任等情形。
