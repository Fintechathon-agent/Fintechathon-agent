## 三分钟演示顺序

1. 先打开固定案例原型，展示“单只资产：投资部分超限”和“逐步改善”，说明两种分母与是否可接受。
2. 打开风控工作台，勾选已确认演示约束，运行健康检查；通过检查后仍未获执行授权。
3. 确认完整计划，再执行模拟；重发同一请求只返回原结果。修改约束后旧确认失效。
4. 点击“运行安全演示”，展示攻击原文、Core/Risk/Action Gateway 阻断节点、固定风险原因与审计；模拟执行工具调用为 0。
5. 换用备用现金不足或缺少调仓执行参数案例，展示 BLOCK/ERROR 后不能通过确认强行放行。

## 边界与保存

- 所有数据均为虚构演示，原工具只有 7 个历史观测。没有连接真实账户或真实交易。
- Core 为确定性的结构化工作流，没有连接大模型服务。攻击演示包含额外的越权探针，验证不可信数据不能改变权限及未确认操作不能执行；不宣称已识别所有提示注入变体。
- 固定案例原型的日志仅在页面内存；工作台的任务、版本、确认、执行标识、风险审计和已同意的 Memory 保存于云端 D1。
- 工作台使用浏览器 cookie 的演示会话，服务端校验归属。不是团队正式账号系统；清除 cookie 后无法用旧链接读取旧会话。只输入虚构资料。
- 当前 A 方案可演示原模拟工具的持有路径。B/C 缺少可信的逐笔调仓执行参数，明确暂停；不能把原型中的预设成功当作正式调仓已接通。
- 每个演示会话最多 20 个任务、800 个审计事件和约 1.8 MB 状态，触及限制时暂停相关功能。必要存储失败时按 Fail Closed 处理。

### 导航修复（工作台版本 2，2026-10-10）

首次部署保留了队友投资组合页面中的 `/merchant` 入口，但本演示没有部署店主模块，点击会返回 404。版本 2 在第四板块的部署适配层将该入口改为“风控工作台”；旧 `/merchant`、`/merchant/` 地址以 302 返回投资组合页。队友的原始页面及主站导航保持其原有功能。

针对本次错误验证了 4 条公网页面路径：风控进入投资页并加载数据、投资页返回风控、两个旧地址正常回退；没有页面脚本错误。证据见 [导航验证报告](workbench/navigation-results.json) 与 [导航截图](workbench/investment-navigation.png)。上方 60 项检查和 8 条工作台流程是版本 1 的首次部署证据，本次没有把它们重新计为版本 2 的运行结果。

上述结果是公开演示的模拟流程与访问边界验证，不等于正式金融系统、真实交易或团队完整生产流程验收。非浏览器 HTTP 测试曾收到托管平台的 HTML 页面；随后改用实际浏览器 fetch 完成公网访问检查，没有更改安全判断来放行测试。
