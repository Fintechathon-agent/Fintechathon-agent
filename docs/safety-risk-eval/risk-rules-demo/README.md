# 固定风险规则交互原型

这是独立的固定案例原型。沿用 Finance Lab 的暖灰背景、深色导航、橙色操作与中文卡片布局。当前只交付原型和架构图；未实现正式风控程序，未接团队审批网关、真实账户或模拟账户。既有规划表 v0.2 保留。

## 打开与演示

2026-10-10 已部署为 [团队可访问的固定案例原型](https://fund-risk-prototype.panxintian44.chatgpt.site)。公网仍使用页面内存模拟，与下方 2026-10-07 的原型范围一致。实际服务端规则与攻防演示请打开 [风控工作台](https://fund-risk-workbench.panxintian44.chatgpt.site)；两者的区别及公网验证记录见 [部署说明](../online-demo/README.md)。

直接用浏览器打开本目录 `index.html` 即可，无需安装依赖或联网。也可用 Node.js 运行 `node serve.cjs`，访问 `http://127.0.0.1:8767`。服务器仅监听本机。

建议用以下顺序做约3分钟的演示：

1. **正常方案**：运行检查 → 确认完整计划 → 执行模拟，强调通过不等于授权。
2. **单只资产：投资部分超限**：看30%／60%的双口径差异，展示执行被禁用。
3. **逐步改善**：先选重点指标 → 重检 → 接受剩余超限 → 确认并执行；再看新增行业超限的反例。
4. **多项复核**：逐项接受回撤、相关性和行业未知，少一项都不能确认。
5. **数据故障**：说明修复类复核不能勾选放行；演示恢复后重检。
6. **结果未知／重复请求**：先核查原请求，成功后重复提交只返回原回执；打开审计字段和架构图。

## 原型与正式能力的区别

- `model.js` 提供固定虚构案例、展示指标与原型状态迁移。金融触发原因由案例预设，不是可以接受任意输入的 Risk Engine。
- 比例按案例目标金额算出，两套分母均展示。历史回撤和相关系数是预设案例事实，不是量化工具真实输出。没有生成虚构市场曲线。
- ETF行业汇总为模拟映射，不是实际基金披露；未知案例不使用缺失标的的映射。不得把固定案例转称真实投资分析。
- 原型回执只在页面内存增加一次演示写入计数，不调用金融工具、不更新正式组合。未知结果不冒充失败或成功。
- 审计只在页面内存，刷新即清空，导出也标记 `prototype: true`、`persistent_audit: false`。演示引用／哈希占位不是加密签名或可信执行授权。
- 浏览器控件禁用用于演示交互，不是正式安全边界。正式执行入口须独立校验可信上下文、风险决定、版本、确认与去重。
- 本轮验证为原型验证，不能替代正式风控单元测试、团队集成测试或模块完成验收。
