# AI 原文与运行审计记录保留、清理提案

状态：待 Core / 数据 / Audit Owner 确认；本轮不修改后端逻辑、不执行数据删除。

## 用户需求与已落地 UI

用户要求模型原文、运行与审计记录保留在后台，定期清理，不在用户前端展示。本轮删除 AI 结果中的“完整模型原文”和“运行与审计记录”及外层折叠框。面向用户的分析结论、依据、待补充信息继续展示。

本轮不修改响应 Contract。前端仍对返回原文与结构化结论做一致性校验，只停止渲染原文和内部编号。此修改不等于接口停止向浏览器返回这些字段，也不代表新增了后台自动清理。

## 当前代码证据

- `chenchen/deployment/worker.js` 的 `ReviewService.persist` 将完整 record 存入 Durable Object Storage，建立 `run:`、`task:`、`idempotency:` 关联键。
- 独立分享 Worker 的 ReviewService 继承此服务；部署候选也保留持久化调用。
- 对上述源文件及现用部署候选的只读检查未发现运行记录的定期删除或 retention 定时任务。此结论是代码检查，不是生产数据库抽样。
- 频控计数淘汰不等同于模型原文/审计记录清理。

## 请 Owner 确认的方案

1. 分别确定模型原文、运行记录、审计凭证的保留期限；由 Owner 确认配置和权限，不在 UI 中硬编码期限。
2. 定时分批清理已过期且允许删除的记录；运行记录与关联索引一致处理，避免悬空 task / idempotency 引用。保留尚有业务引用、未终结流程及要求保留的审计凭证。
3. 清理任务需可重入、可恢复、有限批次，记录执行时间、数量和失败原因；运维日志不包含完整用户输入、模型原文或密钥。
4. 若进一步要求原文/内部编号不进入浏览器，需要另行明确公开响应与内部审计响应 Contract，并调整当前客户端一致性校验；不得只隐藏页面后宣称数据已隔离。

## 验收要求

用合成记录验证到期边界、未到期保留、业务引用保留、关联索引一致性、任务重复执行、失败重试和无敏感内容日志。Owner 批准后再实施后端变更与数据库验收。
