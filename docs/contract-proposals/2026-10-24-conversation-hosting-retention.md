## 当前实情

- GitHub Pages 只发布静态 UI，无法运行 Python 和 SQLite。个人预览的 `conversation-config.json` 保持 `endpoint=null`，不能把页面可访问称作线上 AI 接入成功。
- 原服务只接受本机客户端、本机 Host、同源 Origin，并使用 HttpOnly、SameSite=Strict Cookie。当前本地启动器保留这些检查且只监听 127.0.0.1；不能直接把 `--host` 改为 0.0.0.0 当作正式发布。
- SQLite 当前仅有 `sessions(id,state)`。对话、账本、偏好及请求去重数据保存在会话 JSON 中，没有上次访问列、统一过期列、正式账户找回或跨设备同步。
- 本地提供只读 `retention_report.py`：列出候选数量，`deleted=0`。报告读取不会更改数据库。不提供删除开关。

## 推荐 HTTPS 方案：同源 Python 服务与持久卷

使用用户已经拥有或另行批准的 Python 容器托管环境，页面与 `/api/assistant/*` 使用同一 HTTPS Origin，SQLite 放持久卷；定期备份与恢复演练。若需多实例，再由后端 Owner 评估托管数据库迁移。

上线前需由后端 Owner 确认并实现：正式登录与会话找回、HTTPS Secure Cookie、代理与 Origin 信任边界、跨用户隔离、CSRF、请求大小与超时、跨进程去重、全局限流及供应商调用预算。Secrets 只从后端运行时注入；不得把 Key 或本机配置放进静态站点。发布时显式设置同源 `/api/assistant/`，先进行云端独立验收，再启用主站入口。

本轮不将其改写为 Cloudflare D1/Workers 服务：Python/SQLite 到 Worker/D1 的迁移属于新的后端与数据方案，需要 Owner 评审。现有 Qwen 分享 Worker 不作本次部署目标，不改变其 Secrets、预算、用户或 API。

## 自动清理建议（默认全部关闭）

| 数据类型 | 建议候选规则 | 当前行为 |
| --- | --- | --- |
| 脱敏运行诊断 | 14 天后候选，先确认是否需保留排错证据 | 后端本地保存，不自动清理 |
| 会话原文 | 90 天未活动后进入复核；完整账本不能随会话一起删除 | 只读报告，无删除 |
| 账本、投资计划、偏好 | 由用户决定；账本删除与遗忘摘要语义分别保留 | 不执行后台批量删除 |
| 请求去重与未知模型请求 | 需与最长重试期、费用核对周期协调 | 不清理，避免重放付费调用 |
| 验收合成数据 | 独立测试会话，可在验收后另行批准删除 | 本轮保留 |

如批准定期清理，建议先新增由 Owner 管理的活动时间与保留类别，定时任务先运行报告模式，核对并备份后再逐步启用。必须记录规则版本、范围、执行时间、删除数量、备份回执；未知时间的数据跳过。不能用前端隐藏来代替后台保存、不能通过前端倒计时伪造清理。
